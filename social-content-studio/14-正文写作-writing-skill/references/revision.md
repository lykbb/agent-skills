# 改稿时先救人，再清句子

这份文件用于已有稿件与初稿完成后的审稿。用户直接给出改稿任务时立即读取；新稿动笔前不加载详细审稿清单。

改稿的目标不是把文章修到无懈可击。先保护已经活着的地方，再拆掉模型摆出来的姿势。

下面七遍默认用于现代白话散文。诗歌、剧本、人物对白和实验写作按具体文体判断，先守住事实或设定边界与用户要求。不要为了让诗歌主干完整、让对白像说明文，改坏原本成立的作品。

## 改稿前锁定范围

用户只要求调整表达时，保留事实、数字、单位、术语、链接、引用归属、表格、图和 PRD 块。记录会影响判断的时间、模型、样本、比较对象与条件词，尤其是可能、通常、不能单独、不能当作固定倍率等限定。发现内容问题，另列建议；没有授权就不悄悄改结论。

优先沿用现有 Markdown 结构。粘贴稿丢了标题、表格边界或代码围栏时，对照原文件恢复能确认的格式，不自行补造缺失内容。保存新稿遵循项目现有的版本规则；覆盖、移动或删除旧稿按用户授权处理。

改完对照原稿：数字与口径是否一致，必要步骤是否保序，限定有没有漏，链接、代码、图表与 PRD 是否完整。删装饰性引号也不能改字符串字面量或直接引语。

## 改稿顺序

- [先看谁在说](#第一遍看谁在说)
- [再看文章有没有往前走](#第二遍看文章怎样往前走)
- [拆掉表演性的中文](#第三遍拆掉表演性中文)
- [听词序、照应、停顿和古意](#第四遍听一遍中文顺不顺)
- [查套话、标点与引用](#第五遍查套话标点与引用)
- [核现实或设定](#第六遍核现实或设定)
- [最后看结尾](#第七遍查结尾)

## 第一遍看谁在说

读完以后回答四件事。

- 现实稿的作者凭什么知道这件事，虚构稿的叙述者此刻能够知道什么。
- 哪一处能看出他真的在意。
- 哪个判断有材料托着，哪个情绪有动作或关系托着。
- 哪几段换一个模型也能原样写出来。

第四类段落优先处理。现实稿补信息来路、作者取舍和具体材料，虚构稿补叙述位置、人物行动和场景变化。没有东西可补就删。

第一人称可以交代判断、研究过程和可核验的计算，声音仍靠材料与取舍。“我自己算过一笔账”要能给出假设和算法；“我一般这样做”“我用过”“我测过”要有用户的真实经历支持。没有习惯材料，就把建议写成“我会”或直接给建议。不要用增加“我觉得”“说真的”“大家想想”修复匿名感，更不能编造亲测来换语气。

## 第二遍看文章怎样往前走

给每段标一个主要作用。动作、事实、解释、例子、疑问、判断、背景或情绪。

连续几段只做同一件事，通常会拖。后段没有接住前段留下的问题、动作或结果，顺序需要调整。同一论点在后章回来，须带来新事实、反例、代价或结果；只把“新增价值”换成“更容易继续”“少一次补救”，仍属复述。留下材料最扎实的一处，其余合并或删除。

再问后一段新增了什么。它只把前段换成另一套说法，直接合并或删除。长文最常见的注水方式就是把一个观点解释四遍。

现实稿给每段写一个不公开的材料出处，可以是用户材料、公开来源或可核验流程。虚构稿改为标出这一段由哪个人物目标、动作、发现或关系变化托住，不给创造出来的细节伪造来源。标记为解释或影响的段落，检查是否补了因果、条件、区别或适用关系；只换词重复原结论，就合并或删除。删到文章长度与材料相称，不替目标字数保稿。

遇到历史、技术、制度和数据，问它正在回答哪一个问题。删掉以后人物选择、风险和判断都不变，这段知识来早了，或者根本不用来。

逐段做删除试验：删后是否损失事实、关系、判断或阅读节奏？没有新增作用就删冗，有作用就保留。不设固定删减比例，不把本例篇幅变成以后所有文章的字数模板。

人物稿看他在哪里，做了什么，遇到什么限制，后来怎样。虚构稿看谁想得到什么，场景结束时什么变了。

整篇靠“第一层”“另一层”“更深处”推进时，把这些路标删掉。让事实差异与读者问题承担连接。

### 对一遍开头留下的账

标题和开头让读者想知道什么？若已给结论，正文有没有拿出值得阅读的证明？逐章指出哪一处兑现了这个期待。一个悬念到结尾都没回答，补材料或改开头；一个答案开头已说尽、后文只重复，重新找推进。

文章反复出现的物件、问题或叙述视角，每次回来是否带了新信息？只做首尾同词，删去这种照应。特殊视角如果中途消失，改写正文使它有用，或去掉开头噱头。

找出最能伤到中心判断的真实反例。它若有力，结论应相应收窄、补条件或改变；改了结论还要回头检查前文，不能只在末段补一句“当然也有例外”。若反例没有可靠材料，标明缺口，不制造一个方便驳倒的对手。

## 第三遍拆掉表演性中文

### 假深刻

圈出所有单独截图很好看、放回正文却没有增加事实、解释或情绪的句子。大部分删掉。

连续几段都用一句短判断收尾，留下最有材料的一处。普通段落回到普通句子。

### 工整病（用户确认 2026-10-24，同日补第二轮）

工整不是错误，处处工整是。同一篇里这几种病常常结伴出现，逐项过：

- **金句收尾全篇限 1–2 处**，放在最要劲的位置；其余小节平平地停在事实上。结尾一段禁对仗金句升华（TED 腔），落在未解决的工程困境、具体制度空白或用户决策矛盾。
- **吊胃口式冒号揭晓**（前半吊一下、冒号后抖包袱，如「一句话：」「翻译过来：」「真正的X在：」）每千字不超过一处；图注、字段、步骤、直接引语与来源列表的功能性冒号不受限。
- **修辞性排比最多两项**，第三项换句式或删；信息列举、清单、真实数据不受限。
- **口径与核验说明**按 [现实稿规则](reality.md#正文只保留读者需要知道的归属) 分开处理：纯出处和内部核验细节移到文末或后台；改变判断的归属、口径和条件留在相关结论附近。重复说明合并，不用层层免责声明替代叙述。
- **路标句只留真正转弯处**（「先看X」「把时间线摆在一起看」「要说清楚的是」这类导航词，段落能靠自身逻辑接住的一律删）。
- **报幕式垫步禁令**（第二轮）：亮判断直接亮，观点句作段落首句。删掉引出观点的情绪预告——「有一个得说透的判断」「还有一盆冷水」「这段历史要克制地用」「查完发现和想的不一样」；铺垫感由事实与转折自身承担。
- **自问自答全篇 ≤2 处**（第二轮）：保留给全文最要劲的转弯（如开篇引擎问、核心悬案问），其余衔接靠上段结论中的实体自然带出下段，不用「凭什么？答案是……」做硬跳跃。
- **案例去对称**（第二轮）：多案例论证写透 1–2 个（有细节、有后果），其余压缩成一句带过或沉来源区；禁止美/英/中式等权罗列与「第一块……第二块……第三块……还有一条底线」的机械推进，改用关系衔接（先说X因为…；X管这头，Y管那头；最后…）。
- **元叙事禁令**（第二轮）：正文禁「本文由 Agent 协作生成」类制作自白——它同时属于读者面制作元信息；第一人称实景只写使用与现场，不写本文的生产过程。

### 假具体

搜索精确时间、天气、神态、房间摆设、烟酒食物和突然出现的原话。现实稿逐项问它来自哪里，会不会改变后文。虚构稿只问它是否属于当前视角，是否影响行动、关系或气氛。

现实稿没有来源也没有作用，删掉。虚构稿没有作用，删掉。不要让装饰细节冒充亲历，也不要让虚构细节变成统一摆放的道具。

### 假口语

“老铁”“兄弟们”“咱就是说”“泡杯茶慢慢说”一类称呼只有当前说话者或人物真会这样说时才留。

不要为了制造活人感主动添加粗口、错别字、三连省略号和括号吐槽。人物身份、实验写作或原始材料确实需要时，按作品本身处理。

问句可以引出真正的困惑，比如什么时候上多 Agent，下一段要给出判断与条件。不要每隔几段硬放一个问句。反直觉要有明确的预期差；笨办法但管用、基本就有数了不能给未验证建议作保证。口语点缀是可选项，一段至多一处可作为密度提醒，不要求每段都凑一处。

### 假读者共鸣

不写「你是不是也…」「有没有发现…」「相信很多人都…」「让我们一起…」来假装对话。读者真会卡的地方，用陈述写出断口，下一段回答。用户指定互动帖、口播话术时除外。

### 抽象名词

抽象名词连续出现时，问清谁做了什么，影响了谁，钱、时间和责任落在哪里。

一句话能换进十篇商业文章，说明它没有当前材料。

### 比喻换场

现代现实散文先把借来的世界写在旁边。道路、战争、建筑、温度、仓储、海洋、身体。

短距离出现三套时先全部还原成本义。本义已经清楚，一个也不用放回。小说、诗歌和抒情写作改看意象是否属于同一套感受与场景，不按数量机械删除。

抽象产品稿尤其容易借用仓库、抽屉、温度、死亡、坍塌、浪潮、钥匙和底座。所写对象并非这些东西时，先删掉。删掉以后意思没损失，就不要换一个新比喻。

## 第四遍听一遍中文顺不顺

这一遍检查现代散文。诗歌分行、人物对白和剧本动作可以使用省略、断句与不完整句，按 `references/formats.md` 和 `references/fiction.md` 判断。

### 主干早点来

圈出“……的，是……”“更……的是”“真正让……的”“那些……的……”和一句里多个“的”。

先找到做事的人，把他与动作放到前面。原因、时间、条件与例子接到后面。

不要机械切短。连续短句会变成鼓点。复杂关系允许用长句讲完，只要主干早点出现。

段落也要有高低差。连续十段都只有一句话，合并其中能顺着读下去的部分。连续几段长度接近，检查是不是每段都按同一模具完成。

### 前一句把什么交给了后一句

顺着每个逗号和句号往后看。后一句接的是前一句刚出现的人、物、动作或结果，通常会顺。它忽然换对象，却只靠“这”“它”“他们”连接，读者可能会认错人。

指向清楚时，删掉重复的主语和机械连接词。两个人同时在场、前一句出现多个名词或中间插入一大段话时，把名字写回来。

长定语尽量拆开。先让人和东西出现，再补它的来历、条件和限制。多个“的”是复核线索。读到名词时已经忘了句首，就重写；主干清楚、定语准确且顺畅时保留。

### 停顿有轻重

读出声。逗号处应当还能接着说，句号处应当已经落下一件事。连续短句像敲桌子就合并，长句一口气没有落脚处就拆开。

短句放在长句后面，确实能压住一句话。每段都这样收尾，会变成模型的固定鼓点。让普通地方普通地结束。

### 动作后面少解释一句

圈出动作、物件、原话和比喻后面的情绪解释。读者已经能看见人物在犹豫、害怕、舍不得或嘴硬，就删掉解释。

留白只省读者能够自己得到的部分。关键事实、因果、人物选择和必要条件仍要说清。

### 白话与古意别打架

检查“买／购买”“改／修改”“看／观察”“用／使用”这类单双音节词。根据说话者和场合选，不要全换成正式长词，也不要为了古意全压成单字。

成语、典故和文言句单独拿出来读。删掉以后更自然，就删。需要紧跟白话解释，也删。它与人物身份、题材和全文语气不在一起，更要删。

### 中文产品与技术稿的七条改法

目标是自然的书面语。把句子放到工位上的讨论里听一遍：像在向同事解释，就保留；像宣讲、说明书或为了显得随意而插话，就改。下表是查找线索，不是自动替换表。

| 原则 | 怎样处理 |
| --- | --- |
| 拆工整排比 | 三连、对仗以及反复的先、再、要看，检查是否只在重复。拆成叙述或合并重复内容；必要维度与步骤照留，不能为了两项上限删事实。 |
| 去说教腔 | 应当、需要、必须、提醒我们，能改为得、要、别或直接动作就改。法规要求、接口约束、PRD 与真实引语保留准确措辞。 |
| 去说明书腔 | 删展示的是、关注的是、需要围绕等开场。图注可以写成“图一：一次模型请求是怎么拼出来的。” |
| 主动句优先 | 能说清执行者，就让他做动作。把范围变更在下一步执行前得到处理改为系统在下一步执行前更新范围。执行者未知或重点确在受影响对象时，保留被动句。 |
| 删空的公文连接 | 从……出发、落实到、基于，删后不损失关系就删。真正交代依据、来源或依赖的基于不删。 |
| 抽象换动作 | 交代谁在什么条件下做什么，尽量给可观察的结果。减少转述造成的信息损失，可写少一层转述，也少一次走样的机会；别写成保证不走样。 |
| 校准语气，保护内容 | 得、要、别可用，不主动塞甩、蹭、脑补等网络表达。token、Top-K、P95 等术语不动；事实、数字、引用、图表、PRD 与限定照留。 |

有依赖关系的“先按范围过滤，再检查有效性，最后选相关内容”可以保留。用“既……又……”表达真实的并列或兼有关系也没错。观察全文是否过于齐整，比数某个词出现几次更有用。

过渡要接住动作。“现在让用户改变主意”突然换场，可以接成“好，现在让用户改一次主意试试”，也可以直接引出那条新要求。选择符合全文语气的写法，不把口语过渡变成固定模板。

## 第五遍查套话、标点与引用

### 先看用途

冒号可以引出图注、解释、字段、步骤或原话。破折号可以作必要补充或转折。大量使用会让文章碎，但不因出现一个符号就改文。网址、代码、机器字段与来源原题不受散文标点习惯限制。

引号（「」、弯引号“”、直引号 ""）默认少用，其中「」最少（用户确认 2026-10-27）：装饰性强调、批量自造标签和给概念套引号，一律改成直接写名词。只在直接引语、被批评的措辞，或需要原样标出的界面文字（同一处引一次）时保留。引用命中套话，也先保护原意、归属与措辞；要转述须说明其性质，不能伪装成原话。

### 查套话的作用

翻案腔按修辞动作判断：先捏造一个读者的误解，再推翻它抬价。不是A而是B、你以为A其实B、看似A实则B、真正重要的是B等，都可能做这个动作。找到实际判断，正面说清，把依据放在附近。真实对比、有来源的误解与修正、必要的反例按内容保留，不因句型相似就删。

三项以上的同构排比先检查内容，重复就合并，机械就换句型。有信息的分类、技术维度、清单与步骤保留。名词化则还原动作：“完成了对流程的优化”说成具体改了哪一步，不凭空填提升数字。

“说白了”“说穿了”“先说结论”是默认要清的套话。更微妙的是、还有一层、只说对了一半、值得注意的是、需要指出的是、从某种意义上说，若只给段落抬价就删；数量、本义、引用与用户明确指定的用法按语境保留。

**时代抬价开场（默认清）**：删「在这个…的时代/浪潮里」「随着…的发展/到来」「毫无疑问」「毋庸置疑」「众所周知」「不可否认的是」等不携带新事实的开场。正文若已在谈时代尺度，直接落到具体机制、数字或案例，不先空喊时代。引用原文保留。

**对举堆砌**：同一段内「不仅…更/而且…」「一方面…另一方面…」若两边信息等价或后半只是抬价，合并成一句正面判断。真有两股力量、两边证据时保留。

**英文夹中路标（默认清）**：删作者自造的 Key insight、TL;DR、Bottom line、Pro tip、Takeaway、Note: 作小标题或段首标签。保留产品名、协议名、界面原文、代码标识。需要小结时用中文直说判断或限度。

下面是默认重点检查的黑话词表，不是事实、直接引语和被讨论术语的禁令。赋能、抓手、商业闭环、价值闭环、能力沉淀、拉通、底层逻辑、顶层设计、认知跃迁、价值释放、能力建设、降本增效、内容矩阵、全链路、组合拳、打开想象空间、结构性机会、关键命题、深层逻辑、技术底座、公共底座、技术主权、单点风险、主脊柱、材料锚点、认知增量、迭代闭环。用来替普通事情抬价时，改成人、动作、钱、时间与后果。

下面这些词只做语境检查。沉淀、颗粒度、对齐、协同、链路、生态位、心智、范式、方法论、核心变量、打法、想象空间、闭环、不丢。化学沉淀、排版对齐、游戏战术、控制回路、“不丢人”等本义准确时保留。

安放、抵达、微光、褶皱、丰盈、滚烫、轻盈、赤裸、剥开、锋利、坚硬、柔软，写具体事物可以用，给抽象概念穿衣服时改写。不要给时间、焦虑、岁月配具体动作来代替说明。

检查脚本的词表与此处保持一致，不能偷偷增加一套禁词。它只能发现句型，无法判断引用、反例或规范性措辞是否有用，人工复核可以保留有依据的命中。

## 第六遍核现实或设定

现实稿核时间、数字、身份、引语、因果与第一人称动作。核验说明留在后台。教学设计、简化算例与真实案例分别标明，不能把推演结果写成上线数据。

表达改顺以后，再找一次含义有没有悄悄变大。技术稿尤其检查这些地方：

- 可选方案不能写成行业标准，能够帮助不能写成保证有效。来源标签有助于识别归属，不代表模型一定理解；独立上下文也不等于运行环境自动隔离。
- “不能单独靠向量相似度判定过时”不能缩成“向量相似度判定不了”；可能漏掉开销不能改成一定漏掉。压缩、缓存、多 Agent 的成本与时延收益保留条件，不默认都省钱。
- 成本名称跟分母一致。总成本除以成功任务数，写每个成功任务的平均成本；失败尝试计入实际产生的费用。简化算例列明假设，不写意思到了就行。
- 单次演示可检查某个机制，不能证明稳定性。同一组测试重复运行、记录模型与配置版本等条件，不能为了拆排比删掉。
- 动作对象与能力边界不能换。截断的是历史，不是下一次请求；取消任务要处理在途调用，不能凭空保证外部工具都能停掉、后续费用归零。
- 去掉冗长免责声明，不等于去掉句子的条件。“如果换了工具仍要逐项盯住”不能改成“换了工具仍要逐项盯住”；“文档描述了校验机制”不能改成“我已验证它有效”。修后逐项对照条件、主语、时态和证据身份。

这些例子用于保护原文含义，不要求每篇稿件补一套技术架构。

虚构稿核人物知道什么、时间空间、伤势物件与世界规则。情绪已经由动作托住，删掉紧随其后的解释。

混合稿核现实中必须准确的部分与创作空间有没有彼此冒名。

## 第七遍查结尾

把最后两段分别删掉再读。删掉更有力，就让文章提前结束。

最后一段重新概括全文，即使概括得很漂亮，也先删掉。前文已经讲明白的内容不需要再证明一次。

**空总结连接（默认清）**：「综上所述」「总而言之」「由此可见」「一言以蔽之」若只是重述前文，直接删段或改成一句带材料的收束（事实 / 动作 / 限度）。04 教程收束写「能做成什么 / 哪步易错」，不用上述词起头。允许的短「启示/限度」句也不靠这些连接词起头（与设计文章冲突裁决一致）。

搜索“时代、文明、未来、世界、历史、奇迹、所有人、全人类”。正文没有持续处理这个尺度，结尾回到具体事实、人物动作或当前判断。用户指定的题目自带这类大词时，标题照用户的写，这条只管正文和结尾。

开头物件在结尾回来时，确认读者对它的理解已经改变。含义没变，不必回来打卡。

## 使用检查脚本

长稿保存为文本或 Markdown 后运行下面的命令。

```text
python3 scripts/check_prose.py 稿件.md
```

脚本默认把套话词表、疑似翻案句、排比、名词化、说教或说明书开场等列为人工复核线索。冒号、破折号与「」对数只计数，不一律判错。代码、网址、表格和 Markdown 引用块不参加句式检查，仍要另核事实；普通内联引语可能命中，回原文判断它是引用还是作者自己的说法。

有明确的严格词表检查任务时，可运行：

```text
python3 scripts/check_prose.py --strict-style 稿件.md
```

这个选项只把硬停词、重点黑话、典型翻案句和模型路标升级为失败项，不增加标点禁令。它判断不了语义和引用身份，不用于逼迫事实、规范条款或原话改写。默认退出 0 表示完成检查；严格模式退出 1 表示这些候选项命中；读取失败或没有可检查汉字退出 2。

脚本不测 AI 生成概率。句长、第一人称、问句和口语化都不保证检测分数；不能把三连排比叫作 AI 作者身份的证据。检查结果也不等于事实核验、敏感词或平台审核通过。

外部检测遵守本 Skill 的检测边界，仅按用户明确授权处理。先确认是否允许提交真实稿件、是否涉及登录或额度；用户已选择只在本地审稿时就不外传。不擅自付费，不给检测结果承诺发布安全，去 AI 味建议仍须人工复核。

## 最后冷读

暂时忘掉所有规则，只回答下面几句。

哪里让我相信作者确实知道这件事。

哪里让我愿意继续读。

哪一段像人在处理一个问题，哪一段像模型在完成写作任务。

哪里能看出作者真实的取舍与倾向，还是整篇都在当四平八稳的“端水大师”。

哪些地方只有抽象概念标签，没有手头动作和物理阻力（参见 `references/human-touch.md`）。

读起来像不像是工位旁边的资深同事在跟你坦诚拆解问题，还是客服腔或领导讲话。

哪句话说得比材料大。

文章在哪一句已经结束。
