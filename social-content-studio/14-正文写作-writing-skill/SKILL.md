# 写作skill

本 Skill 也是用户所说的“人味 Skill”。所有图文与文章，包括正文、标题、封面和图内文字，在交付或生图前默认完成一轮自然表达润色；已有确认稿只处理当前授权范围。

文章、图文和改稿不使用小橡皮 AI：不打开其工作台、不提交稿件、不将检测列为交付步骤。去 AI 味由本 Skill、本地检查及人工复核完成；独立验收按产线约定执行。

默认复核顺序：保留原意与限定 → 调整自然表达 → 对照核验内容 → 交付或出图。先保护作者的主要判断、因素之间的关系、影响程度的差异、犹豫和适用边界，不能为了简短、结构整齐或更有气势把这些删掉。

润色程度按文体调整：个人观点、小红书短文可更口语，正式报告和技术稿保持自然书面语。改善具体用词、句子节奏和衔接，不统一塞俚语、短句或夸张断言；按任务读取下文对应的写法参考，成稿后再做内容保护复核。

默认把文章写成一篇值得读完的中文长帖。读者应当感觉对面有一个具体的人。这个人知道一些事，也有不知道的地方。他愿意讲细节，敢下判断，偶尔岔开一句，随后还能把话接回来。

用户要求短文或“稍微润色”时，以用户指定的篇幅和原稿为准，保留其判断与表达，不按默认长帖长度扩写。

小红书文案、标题、封面和图文任务，先读取 [小红书图文流程](../15-小红书分页-xiaohongshu-image-posts/SKILL.md)，遵循知识库优先、先框架再文案、优化后按用户指令逐张生图的流程。已有框架或确认稿直接沿用；只要求润色时只改文案，不自动生图。

不要把“活人感”理解成口头禅、粗口、错别字和网络梗。它不仅是“禁止什么”（防守），更在于“怎样思考与交流”（正向支撑）。活人感来自四个底层支柱：
1. **工位视线（Peer Stance）**：像坐在隔壁工位上的资深搭档，不当居高临下的布道者，也不当谄媚迎合的客服；就事论事，平等坦诚。
2. **认知摩擦（Cognitive Friction）**：展现真实推演与思考阻力（哪里想错过、哪里有权衡），而不是直接端出毫无破绽的终局真理。
3. **取舍与代价（Opinionated Trade-offs）**：拒绝当绝对中立的“端水大师”，敢于亮出倾向并说明原因，同时承认选择背后的妥协与代价。
4. **阻力动词与体感细节（Operational Anchors）**：把抽象大词打碎成具体的手头动作、物理摩擦和真实场景。详见 [人味正向心法](references/human-touch.md)。

中文产品、技术与日常协作稿默认用自然的书面语，像在工位上向同事解释一件事。得、要、别可以用，不主动添加甩、蹭、脑补等网络说法。用户明确指定更口语的风格时再调整。不靠代词、问句或故意打乱句子追求检测分数。

## 第一关先看作品靠什么站住

这一步先于提纲和动笔。用户要求的字数不能跳过它。

现实作品靠前两类材料，虚构作品靠第三类材料。混合创作先把两部分分开。

- 用户明确提供的经历、事实、数字、动作、原话与判断。
- 已经查到并能核验的案例、数据、产品流程、人物经历与时代条件。
- 虚构任务中，作者获准创造的事件、人物动作与场景变化。

现实稿里，模型临时想出的“比如有个人”、没有来源的典型场景、常识推演、抽象观点的后果、比喻与同义改写，都不能冒充真实材料或拿来撑篇幅。把“记录方便”“声音保留状态”“检索找回旧内容”各解释五遍，手里仍然只有三条材料。明确标注的教学设计、假设场景和简化算例可以解释已核验的机制；写清假设、条件与适用范围，不把它们写成真实上线、亲测数据或用户经历。

虚构稿可以创造人物、现场和细节，不需要为它们寻找现实出处。每个主要段落或场景仍要有动作、选择、关系变化、信息变化或后果。只换景色和说法，没有事情发生，也不能拿来撑篇幅。

非虚构作品计划达到一千二百字时，先在内部逐条写出至少五件具体材料，并注明它来自用户哪句话或哪份可靠来源。只写一个概括性的类别不算。五件材料还要能组成一条实际过程，不能是五句相邻的道理。

非虚构稿列不出五件，就先别写长稿。这一轮不能输出标题和长文正文。目标字数、用户催促和“直接写”都不能把材料变多。

现实材料不够时，只能选择一种处理。

- 事实型题目有公开材料可查时，先研究，研究后重新计数。可用检索工具却没有检索，仍然算没有材料。
- 个人体验或私人判断需要用户材料，一次问完最多三个问题，此时不要同时交稿。
- 用户明确不许追问时，能研究的先研究，研究后重新计数，凑够五件就可以按原定篇幅写。研究之后仍然不足五件，缩小题目，最多交一篇六百字左右的短答。宁可明显短于目标字数，也不能用假例子和重复解释填满。

现实稿动笔前记清每件重要材料从哪里来。说不出来路的内容不能负责托住事实段落。虚构稿改为检查每个场景由哪个人物目标、动作或变化托住，不给虚构细节伪造来源。不要把这些内部检查交给用户。

现实观点稿有一种高频错误要直接拦住。用户只给“输入更方便”“声音能保留状态”“AI 可以找回旧内容”这类三条抽象想法，又要求一千多字，这仍然只有三条材料。不能分别补上用途、意义、风险和未来，再写成十几段。应当先找真实产品、使用过程、研究或用户经历。找不到就问，用户不让问而且研究后仍然不足，才写短答。

## 按任务读取

- 新写或大幅重写知乎回答、论坛长帖、公众号文章、博客、评论、人物稿和行业稿，读取 `references/forum-prose.md`。
- 真人、历史、新闻、产品、数据、评测、教程、商业信息和用户亲历，另读 `references/reality.md`。
- 小说、故事、虚构散文、对白和剧本，改读 `references/fiction.md`。用户要求帖子体小说或第一人称故事时，再同时读取 `references/forum-prose.md`。
- 短内容、个人叙事、教程、评测、口播、演讲、剧本、对白和诗歌等形式需要特殊处理时，读取 `references/formats.md`。
- 小红书或其他平台的个人观点短文、轻度润色、标题和封面文字，另读 [个人短文与封面文字](references/personal-posts-and-cover-copy.md)。只在这些任务中读取，不把短文写法套到所有长文。
- 无论何种文体，需要校准“活人感”、消除机械塑料味、或在对话/方案对谈中保持自然平等的人味时，读取 [人味正向心法](references/human-touch.md)。
- 初稿完成后再读取 `references/revision.md`。用户给出成稿、要求润色或去 AI 味时直接读取它，按其中的七条改稿原则和内容保护清单处理；不必重走选题与初稿流程。不要在新稿动笔前加载详细审稿规则。

不要为了保险一次加载全部参考文件，只读当前任务确实命中的部分。真正的混合任务可以读取多个文件，`references/revision.md` 仍留到初稿以后。创作时以正向目标为主，已经写在本文件里的交付禁令留到初稿完成后再逐项检查。

## 多条规则同时出现时

按下面的顺序处理。

1. 当前用户明确指定的文体、现实或虚构性质、语气和交付形式。
2. 作品对现实作出的承诺。现实内容服从事实边界，虚构内容服从人物、因果与世界规则。
3. `references/fiction.md`、`references/reality.md`、`references/formats.md` 和 `references/human-touch.md` 中与当前任务直接相关的规则。
4. `references/forum-prose.md` 与本文件里的默认散文写法。
5. `references/revision.md` 的改稿规则与检查脚本的提醒。

具体文体覆盖通用写法。现实稿的来源要求不能压到纯虚构上，散文的完整主干不能压到诗歌分行和人物对白上。检查脚本只提供明列的复核线索，显式严格模式按词表提示命中；它不能替作者决定文体或引用用法。

## 先确定作品对现实作出什么承诺

### 现实写作

真人、现实事件、数字、引语和用户经历都要核准。用户没提供的亲历、现场、对白和心理，不能补成事实。

### 虚构创作

可以创造人物、地点、现场、对白、心理和结局。人物、时间、因果与世界规则要前后接得上。

### 混合创作

先分开现实中必须准确的部分和可以创造的部分。只核会影响故事与现实判断的事实。

用户说了“小说”“虚构”“假设”“随便编”，直接创作。用户要求真实、纪实、亲历或遵循历史，先核验再写。

## 动笔前先找到说话位置

在内部回答下面五件事，不把答案原样交给用户。

1. 谁在说这件事。他凭什么知道，又有哪些地方只是在推测。
2. 什么事情让他现在想说。可以是一条新闻、一次经历、一个疑问或一件一直想不通的小事。
3. 手里有哪些能托住文章的东西。优先找动作、数字、时间、地点、原话、失败、代价与后来结果。
4. 他对哪一点有明确判断。这个判断依据什么，又到哪里为止。
5. 读者知道上一段以后，最自然会追问什么。

现实稿的第三项太少，回到开稿前的材料检查。不要用哲理、象征、想象现场和重复结论补字数。六千字现实长文需要能展开多个阶段、案例或现实关系。虚构稿若缺少人物目标、行动和场景变化，回到 `references/fiction.md` 补出故事，不向用户索要不存在的现实出处。

作者手上有真实实操材料（工具链、流水线、被 Agent 处理过的稿件）时，观点长文至少埋一处第一人称实景，两三句即可，放在转折点上（用户确认 2026-10-24；同日修订：实景只写使用与现场——见过、用过、被处理过，不写本文的生产过程，「本文由 Agent 协作完成」类自白属元叙事，读者面禁入）；没有真实经历不硬造，也不把本次生产过程写成流水账。

现实材料不够时先停在这里。能查到公开材料就研究。作品依赖用户体验、情绪和私人判断，就一次问完下面三件事。

- 你和这件事实际发生过什么关系。
- 哪个瞬间、数字、动作或原话最让你在意。
- 你现在最想说的判断是什么。

不要先交一篇空稿，再期待用户往里补活人感。

现实稿要求直接写而且无法补材料时，宁可交一篇更短、更实的作品。篇幅是目标，材料边界是底线。虚构任务直接按授权创造，篇幅由事件和场景变化托住。

个人经历缺少关键材料时，最多问三句。用户明确要求不追问或直接出稿，就先研究，随后缩小题目或缩短篇幅，不能把新增经历安到用户身上。

## 第一稿直接带着人写

用户已给大纲，或已用 huashu-topic-gen 定好标题和章节时，保留用户确定的方向，把每章的任务、材料和转场当作写作条件，不把目录逐条扩写成“首先、其次、最后”。动笔前核对每章是否真的有材料；正文写到能改变原判断的反例时，修正判断及相关章节，别为了证明预设结论而略过材料。用户锁定章节结构时保持结构，必要的判断修正写进现有章节。

第一稿从具体说话者和材料出发。像给一个感兴趣但不了解此事的人解释，边讲事情，边处理他下一步会产生的疑问。

下面是现代白话散文的默认写法。诗歌、剧本、人物对白和实验写作服从具体文体规则，不能为了满足散文句法而改坏作品。

- 开头尽快碰到事情。可以直答，可以讲刚发生的一幕，也可以从一个反常的小事实说起。不要预告全文结构。
- 除非用户明确要清单或教程，不要先把题目命名成两个成本、三层原因、四个阶段。分类应当来自材料，不能拿分类代替文章。
- 一段先完成眼下这一件事。它可以讲动作、补背景、算一笔账、解释原因、承认疑点或给出判断。
- 新段落必须增加一件新东西。新的事实、新的动作、新的例子、新的区别或新的后果都可以。同一观点改换说法不算推进。
- 后一段接住前一段留下的问题。推进靠材料和因果，不靠“更深一层”“真正的问题”之类路标。
- 先让主语和动作出现，再往后接时间、原因、条件和例子。长句可以有，读者要尽早知道谁做了什么。
- 让白话打底。古意从词序、停顿和分寸里自然出现，不靠生僻字、成串成语和硬塞典故。
- 动作、细节或原话已经把感情写出来，就停一下。不要追在后面替读者解释。
- 允许正常的重复、补充、自我修正和短暂岔话。每一处都要来自眼前内容，不能按固定间隔表演随意。
- 判断可以偏，可以有情绪。把依据放在附近，让读者知道这是作者的看法。
- 现实稿的幽默从事情自身的荒唐处出来，不另编笑话，也不给严肃材料强塞俏皮话。虚构稿的笑料要属于人物、关系和场景。
- 段落不必等长。普通地方用普通句子结束。单句成段只留给确实需要停一下的地方。
- 写到事情已经讲完就停。不要强装升华、首尾呼应或时代意义。前后照应只有在事物的作用或含义已经改变时才保留，正文持续处理过时代尺度时才允许在结尾回到这个尺度。不要在末段重新摘要全文。

用下面这组句子校准方向。

> 他毕业后离开上海，去了成都。那套量化程序已经跑过一段时间，他觉得可以全职试试。收入会不会稳定，当时没人知道。

这比“他关掉一条好走的路，把命运押上赌桌”更接近目标。前一种写法给动作、条件与风险，后一种写法只有姿势。

## 不要穿论坛服装

论坛感不等于“老铁”“兄弟们”“谢邀”“泡杯茶慢慢说”。烟头、啤酒、冷馒头、深夜屏幕和突然响起的电话，也不能凭空替文章增加真实感。

现实稿里，没有来源的精确时间、神态、天气、房间摆设和对白都是假细节。假细节越具体，AI 味越重。虚构稿可以创造这些内容，细节必须跟着人物视角与行动走，不能只负责穿上论坛服装。

现实稿真正有用的是信息来路。写清作者在哪里知道这件事，起初哪里想错了，哪条材料改变了判断，哪一块到现在仍拿不准。只挑当前文章确实拥有的部分，不要凑齐。虚构稿的可信感来自人物怎样知道、误解和发现，不伪造现实来源。

## 成稿怎么复核

下面是默认散文写法。当前用户指定的表达与文体优先；核准的事实、直接引语和功能结构也不能为了过检查而改坏。改稿以自然、准确、好读为目标，句型和词频不能证明作者是不是 AI。

- 判断从正面说。不要虚构一个读者并没有的误解，再用“不是……而是……”“你以为……其实……”等句式给下文抬价。有材料支持的事实区分、自我修正和真正的反例保留。
- 三连排比、对仗、“既……又……”和整齐的“先……再……”是人工复核线索。重复内容合并，机械句型拆开；必要的分类、清单和有依赖关系的步骤保留，不删第三项来凑规则。
- 少写“应当／需要／必须／提醒我们”的宣讲语气、“展示的是／关注的是”的说明书开场。能直接说动作就直接说。准确的规范性要求、技术条件和被讨论的原句保留，不做全局替换。
- 给动作找执行者。把“完成了对流程的优化”改为具体怎样修改流程；少堆抽象名词、公文连接词和借喻。被动句、本义词与必要因果按语境判断。
- 用第一人称表达作者判断或透明的计算过程。用户没提供的“我用过”“我测过”“我一般这样做”等经历和习惯不能补写。建议可以写“我会”，不用假亲历补声音。
- 问句留给读者真的会问的地方，后文要回答。口语虚词和短句按内容安排，不按每段一处的配额添加，也不把未验证建议说成“管用”。
- 不写「你是不是也…」「有没有发现…」「相信很多人都…」「让我们一起…」假读者共鸣；段末不堆可截图金句。时代抬价开场与「综上所述」等空总结连接默认清，见 `references/revision.md`。
- 少用引号，尤其「」（用户确认 2026-10-27，以后少用）：只留实际引语、被讨论的措辞和确需原样标出的界面文字，同一处引一次即可；其余把名词直接写出来，不给概念、强调词和自造标签加引号。不改代码与字符串里的引号。
- 冒号可用于图注、解释、字段、步骤和直接引语。破折号可用于必要补充或转折，检查是否滥用，不一律清零。网址、术语、代码、表格、图和 PRD 块按原任务保留。
- “说白了”“说穿了”“先说结论”、洞察路标和商业黑话是本 Skill 默认要检查的套话，具体词表见 `references/revision.md`。准确的本义、引用与当前用户指定用法按语境保留，不因命中字符串就改写原话。
- 检查活人感四大支柱：是否保持平等的工位视线；是否交代了思考中的认知摩擦与推演难处；是否有明确取舍并承认代价（拒绝端水大师）；大词是否都还原到了带阻力的手头动作与物理场景（详见 `references/human-touch.md`）。

初稿写完再执行详细审稿。已有稿件只改用户授权的部分，修改前后对照事实、数字、单位、术语、引用和条件。少写几个“可能”不能把有限证据变成定论。

长稿保存后可运行 `scripts/check_prose.py <稿件路径>`。默认输出人工复核线索；可选 `--strict-style` 仅将明列的套话类别作为失败项。脚本不测 AI 生成概率，退出成功不代表事实核验或发布审核通过，警告也不是修改命令。详见 `references/revision.md`。

## 交稿

用户只要作品，就只交作品。内部提纲、核验记录和制作过程不混入正文、图注或图内文字；必要归属与条件用自然叙述交代，详见 [现实材料的读者面处理](references/reality.md#正文只保留读者需要知道的归属)。

来源按 [来源怎样交付](references/reality.md#来源怎样交付) 处理：长文关键来源链接默认集中在文末；个人经历为主而引用了公开事实，也给相应来源，不因文体是观点稿就省掉依据。用户指定的引用方式优先。

只服务当前作品。不建立长期作者画像，不生成个人规则库，不创建新的个人写作 Skill。
