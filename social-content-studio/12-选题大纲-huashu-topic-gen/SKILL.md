# 中文长文选题与大纲

负责选题、标题、开头和大纲。正文写作与大幅改稿交给 writing-skill。本 Skill 的目标是让作者知道：读者为什么点进来，为什么读下一节，每一节凭什么成立，读完对同一个问题的理解改变了什么。

用户已定题就围绕该题工作；只要标题或局部调整，就只处理对应部分。保留用户确定的标题、立场、文体、平台和篇幅。参考文章可借结构与方法，不能借用作者的经历、原话、数据或结论充当用户材料。


## 01 情感倾向闸门（选题后、初纲前）

入口为 **01 深度观点** 时：输出标题与完整初纲前，先写（或向用户确认）`情感倾向`（批判 / 认同 / 共鸣 / 警醒 / 厘清边界 / 其他）及一句话对象。用户未定且材料无法唯一推断时，**停下来问用户**，不得默认中立说明文。审纲交付须复述该项。04/05 跳过本闸门。

## 先找文章的发动机

结构增量与「分点=阶段」硬规则见文末「设计文章参考增量」及 [冲突裁决](../references/design-article-ref-lessons.md#冲突裁决必读)；与本节「每节改变理解 / 禁并列概念目录」同向，不另立第二套大纲哲学。

写目录前，先从已有材料中提取四件事：

1. **一个可被反复检视的对象**：一句需求、一张图、一项功能、一个决定、一份文档、一段经历。抽象主题需要具体载体。
2. **一个真正值得追问的问题**：读者看见对象后会问什么？这件事为什么现在值得写？作者和读者分别被什么问题牵住？
3. **作者暂时的判断及边界**：不是正确口号，而是可能被反例修正的回答。区分亲历、可核事实、推测和价值判断。
4. **能改变判断的材料**：现场、截图、版本对比、决策过程、失败、研究、反方实例。材料不足，列出缺口，不造现场、对话、测试或数字。

一句话写出全文的读者路径：读者起初怎样理解这个对象，经历哪几次信息或判断变化，最后又怎样理解它。找不到这条线，先不要写四个并列概念的目录。

## 标题：给一个阅读承诺

标题可以有两种主要承诺：

- **先抛未解之事**：具体事物或选择，加上一个读者想知道的原因、后果或身份。例：[案例 1](references/casebook.md)用不起眼的批注连接一个大问题；[案例 2](references/casebook.md)暂不揭示叙述者。
- **先亮判断，留下证明**：[案例 3](references/casebook.md)直接给出概念关系，读者仍要看论证、反方回应和实际意义。标题不是必须藏答案。

先从真实材料里找物件、动作、代价、时间、角色错位或读者误解，再写标题。不要先套“什么是”“揭秘”“几招”等形式，也不要为悬念隐去主题。数字、身份、结果和亲历必须真实。给多个备选标题时，说明各自承诺了哪篇不同的文章；用户锁定标题时不擅改。

## 开头：给正文能兑现的理由

钩子不是“制造待解决的矛盾”这一种公式。可用的入口包括：一件意义暂不明朗的实物或记录；一个有代价的选择；结果与预期相反的经历；读者也会误判的现象；一个能贯穿全文的叙述者视角；或先亮一个需要证明的大胆判断。优先选文章本来就有的材料。

开头先让读者看到动作、细节、证据或明确问题，再解释概念。写钩子时同步写下：读者此刻会追问什么，正文哪一节兑现，结尾是否让开头的物件或问题获得新含义。若删掉开头悬念也不影响正文，它只是包装。若只有漂亮开头而没有材料支撑，标待补。

## 结构：每一节改变一次理解

文章不是把几个正确概念排成章节。每章回答上一章留下的疑问，并带入新事实、解释、反例、决定或后果。概念只在解释材料中的问题时出现，不按术语排队。可选的推进方式：

- **同一物件的意义变化**：物件初看是什么，后来如何被行动和经历重新定义；见案例 1。
- **过程本身成为结构**：读者跟着一个真实制作或决策过程走，形式与主题互相证明；见案例 2。
- **沿一条变量重排概念**：新名词看似越来越多，找到贯穿它们的变量，再回应最强误解；见案例 3。
- **沿有代价的选择追因**：决定先行，再交代机会、阻碍、试错和承担的后果；见案例 4。

这些是可选择的结构发动机，不是四步模板。选与当前材料匹配的一种，必要时组合；不要因为案例吸引人就硬套第一人称、自述体或“对抗 AI”。

观点文还要经历一次真正的压力测试：观察是什么，最初解释是什么，哪个反例最伤这个解释，主张因而要缩小、补条件还是改写？反方若有道理，写清仍然作出某个选择的理由、代价和适用范围。文章的深度来自判断被材料改变，不来自多放几个心理学或社会学名词。

## 每章写成可动笔的说明

用户已定题，交一份完整大纲，而非让用户选三四个同义方向。每章按需要写明：

- **本章任务**：它改变读者的哪个判断，为什么必须放在这里。
- **待回答的问题**：它接住上一章留下的什么。
- **写法与材料**：先写什么，再比较什么；明确亲历、截图、测试、研究及待核来源。
- **本章所得及限度**：材料能证明到哪里，不能推出什么。
- **转场**：本章产生的下一个真实问题，而非“接下来让我们看看”。

主问题、临时判断、最强反方和结尾落点要对应同一条线。结尾可以回到开头，但只有当读者对那个对象的理解确实变了才回；无需强行金句或升华。

## 示范：把“高级感”从概念目录改成推进线

以下只是结构演示，不能冒充作者已经做过的实验。应先取得真实生成结果、设计版本或需求沟通记录。

- 平铺目录：加工流畅性、格式塔、信噪比、极简主义、文化资本、提示词。每章都对，但调换顺序仍成立，读者看完仍可能只记得“少即是多”。
- 可推进的路线：同一句“做得有高级感”进入一次真实的 AI 生成或产品评审；先观察 AI 和人各把它理解成什么；发现“少一点”解释了部分例子，却解释不了繁复但仍被认为高级的作品；于是把问题从元素数量改为秩序、取舍和受众预期；再问产品经理如何把这类感受转成可讨论、可验证的要求；最后回看开头那句话，它已从审美要求变成需要澄清的沟通任务。
- 这条线仍需证据：具体输出对照、评审原话、不同受众判断，或可靠研究。没有这些，先给取材和验证方案，不伪造一个完美故事。

## 交付前审核

- 标题与开头分别承诺什么？正文具体哪段兑现？若标题已亮结论，正文有没有足够值得看的证明？
- 移走或删除任一章，读者理解是否仍不变？若是，章节可能只是并列罗列。
- 每章到底增加了什么材料或修正，而非增加了什么术语？
- 最强反例是什么？它把观点改到哪里？有没有把反方写得过弱？
- 开头对象在结尾获得的新含义是什么？没有变化就别假装首尾呼应。
- 所有经历、数字、引语、效果是否有来源？缺口是否直接标出？
- 读者能否依据大纲开始写每一章？只剩章名和抽象论点就继续深化。

## 交付与平台

未定题时给 3 至 4 个确实不同的方向，说明读者承诺、可用材料、工作量及缺口；定题后给一份可写的大纲。少数派侧重真实过程、证据与读者能带走的判断；人人都是产品经理侧重问题定义、案例、取舍与执行边界；公众号按目标读者调节叙事节奏。平台差异不替代文章的主线。

## 案例库与后续增补

需要设计强标题、开头、叙事结构或分析参考文章时，按文体选读 [案例库](references/casebook.md) 中相关的 1 至 2 则；不要把所有案例同时套进一篇文章。用户以后提供好文章并要求吸收时，先读原文，说明真正可迁移的新写法和它的局限，再按案例库末尾的字段增补。若只是旧模式的重复，补充原案例的适用边界，不堆相似卡片。案例库记录方法和来源，不收录可直接挪用的原文段落。原链接失效时，可用本地案例卡讨论写法；需要核对原话或事实时，寻找作者的其他公开版本或请用户提供其持有的副本，无法核对就明确说明，不凭案例卡重建原文。

## 设计文章参考增量（2026-10-24）

共享原则见 [design-article-ref-lessons](../references/design-article-ref-lessons.md)。本 Skill 只补大纲结构增量：

- **分点 = 过程阶段或决策闸门**（业务分析→资源→优先级→方案→闭环…），禁止「可调换顺序仍成立」的概念目录；「N 条原则」体禁止作大纲骨架，仅可作文末检查附录。
- **工整病上限（用户确认 2026-10-24，同日补第二轮）**：01 观点文骨架与并列列举避免层层恰好凑三，全篇三分结构最多两处，其余照实——该四就四、该一笔带过就带过；事实本身的数目（论文列五项、系统设三参数）照实不算凑。分析框架（如 Agent 三维拆）不受此限，修辞与章节骨架受此限。层层都是三是最显眼的生成痕迹。成稿后的同族句式病见 [14 revision 工整病](../14-正文写作-writing-skill/references/revision.md)。案例规划同理：多案例论证在大纲层就定 1–2 个深度个案（标明细节与后果），其余标「一笔带过」，不摊成美/英/中式等权罗列。
- **可选发动机**：同一情景案例贯穿全文；用户旅程分章（每章只改一个阶段的理解）；服务/协作题可用四方推进（由内而外 / 由外而内 / 自上而下 / 自下而上）。
- **顺序闸门**：先问题 / 人群 / 目标 / 成功指标，再功能与交互；**禁止从页面或表现层开工**。UX 五层/冰山只作分析草稿，正文与大纲须落到材料。
- **AI/Agent 题**：先三维拆——用户怎么输入、Agent 怎么对外行动、内部状态怎么管；缺一维标缺口。
- **模糊视觉任务**：大纲拆成需求澄清→受众→信息整理→字体/图形/构图/配色→细节，再交 17 选型。
- **观点文立意**：问题定义 + 研究/权衡 + 责任，不是只产出视觉稿。

## 按入口默认（01 / 04 / 05）

被入口调用时切换发动机，细则见 [genre-defaults](../references/genre-defaults-01-04-05.md)；不替代上文「每节改变理解」硬规则在 **01** 上的效力。

| 入口 | 大纲发动机 | 交付重心 |
|---|---|---|
| 01 | 判断推进 / 阶段改变理解 / 反方压力 | 读者理解如何被材料改写 |
| 04 | **步骤闸门**（前置→步骤→翻车→验收） | 可照做；禁止概念目录与行业升华骨架 |
| 05 | **事实→验证/对比→限度/尚不知** | 短纲；禁止硬凑深度反方结构 |
