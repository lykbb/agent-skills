## 按入口的增量规则（写入 Skill 用）

### 01 / 人味 / 大纲（相对旧 lessons 的新点）

1. **个案边界**：个人长期使用/漂流体验可作主线，文内或收束标明「个体经验≠普遍结论」。
2. **分线评判**：产品长案例把「美学/交互巧思」与「性能/续航/散热等实用缺陷」分开写，勿混成一句端水；收束允许「错误可以闪耀，但错误仍是错误」式判断，禁止空时代升华。
3. **AX 三层（可选结构）**：写 Agent 体验时可用「用户如何表达意图 · Agent 如何作用于外部世界 · 内部上下文如何管理」组织章节；与既有「旅程/阶段推进」兼容，**不**另立第二套大纲哲学，也**不**替代「每节改变理解」。
4. **委托信任三词**（写委托式 AI 时可用）：可观察、可解释、可介入——旁置材料，勿当空口号。

### 04 教程

1. **三截步骤链**：原则/约束 → 可复用 Skill 或检查清单 → 组件库/系统接入；每截写清完成标准。
2. **规范进 Skill**：正反例 + 情境（语调/状态）矩阵，写成可执行指引，禁止只写「我的十年心得」散文。
3. **翻车点**：AI 辅助流程必写幻觉风险、人工核验节点、意外发现如何处理；文中效率%仅可作作者经验，**禁止**写成行业基准。
4. **忌升华**：教程收束停在「能做成什么 / 哪步易错」，不升行业评论（强化 04 骨架，不改字数默认）。

### 05 资讯·调研

1. **原文先行**：官网、官方博客/播客、发布页；再抽可核事实（版本、日期、地区、机型）。
2. **对照再判突破**：与既有技术或竞品做**任务级**对照（响应是否等待识屏、默认动作是搜索还是丢给 LLM 等）；再写真突破 / 新鲜感 / 常规。
3. **资讯 vs 调研深度**：短讯可停在事实+一句改变了什么；调研须有试法或对照表 + **界限专段**（不写「什么都想要」）。
4. **日期来源**：关键结论旁置来源与核验/发布日期；个人实测标明时长与对象版本，不作通用排行。
