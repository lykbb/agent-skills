| 看似冲突 | 实际怎么做 |
|---|---|
| 「分点=阶段」vs 旧「每节改变理解」 | **同向强化**：阶段推进是实现「每节改变理解」的默认形态；禁止可调换的概念目录 |

| 编辑插画封面 vs 写实混搭默认 | **正文保持写实混搭**；封面选型统一见[视觉风格表](wechat-visual-style-menu.md)，按题选择，不把单例设成统一默认 |

| 写实为主 vs 流程/分栏卡 | **写实为主、按需混用**不变；说明图用流程/分栏，修饰图用实景/章节停顿；卡片仍 ≤1–2 |

## 总原则：学 / 不学 / 年代过滤

### 学

1. **人味**：情景带读、同一案例贯穿、算账与代价、承认限度、错误归系统不归咎用户、结尾可拒空总结。
2. **分点**：优先等于过程阶段 / 用户旅程 / 决策闸门，不是可调换的概念目录；章末可用短「启示/限度」句（不强制小标题字样）。
3. **标题**：主判断或主对象进标题；副信息装范围/边界；忌年份工具名撑深度；慎用「万字干货/诚意之作」腔。
4. **配图**：每图有存在理由；先标修饰图 vs 说明图；看得清 > 漂亮；节点少、手机可读；开篇情境照优先。
5. **AI·Agent 边界**：先人对齐需求；是否适合用 AI；能力披露与确认点；解释≠已核验推理；证据支持与来源位置按14处理；禁拟人夸大；错误态与人在环。

### 不学

1. 过时工具操作链（某年版 Figma/ChatGPT/DALL·E/Napkin 等）。
2. 乱/旧流程图成图：密 UML、状态机教材扫描、Mermaid 编辑器整窗当终稿。
3. 岗位薪酬教条、厂商设计系统细节、MCP/组件映射工程手册。
4. 已与现有 Skill 重复的表述（四大支柱、写实混用、禁元信息、材料门槛等）——只补尚未写清的增量。

### 年代过滤

| 年代感 | 处理 |
|---|---|
| 旧文但人写的过程/语气 | 提炼人味与分点 |
| 旧文但工具/UI/薪酬 | 不进规则正文 |
| 新文但工程过细 | 原则可迁，实现细节不进内容 Skill |
| 国际指南（PAIR、NN/g、UX of AI） | 迁信任/解释/边界原则，不迁具体产品 UI |

## AI 边界短清单（选题 / 核验 / 写作共用）

1. 解释与逐步「思考」**不等于**已核验推理；关键结论须有来源支持或按依据写成推断。链接位置按 [14 来源交付](../14-正文写作-writing-skill/references/reality.md#来源怎样交付)，不等于逐段插链接。
2. AI 产品稿必核：错误态、能力边界、版本/地区；先过「是否适合用 AI」。
3. Agent/自动化：写清确认点与停止规则；高风险动作无人在环则标缺口。
4. 错误与失败不归咎用户；校准信任（防过度信任与无端怀疑）；能力披露。
5. 禁止拟人夸大（「我思考了」）；预测/自动化须透明、可控、可反馈。
6. 生成内容（含配图文案）须人工筛选与事实核查后再进正文/上图。
