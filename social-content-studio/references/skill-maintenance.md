# Skill 维护注意事项（必读）

**何时读**：用户提到维护 / 改 Skill / 完善产线 / 入库规则 / 优化流程，且**不是**在写一篇具体文章时——**先读本文件再动手**。写文章走 01–05 入口，不走本清单。

**谁拍板**：用户确认 > [冲突裁决](design-article-ref-lessons.md#冲突裁决必读) > pipeline/checkpoints > 各 Skill 更早硬规则 > 参考包增量。

## 工作方式（用户已确认，2026-10-24）

- **用户不逐条拍板条文**。执行方负责：对照现有硬规则做冲突检查，并判断「加进去有没有实质改进」；只把无冲突、有改进的薄补丁写入对应小 Skill。
- **验收标准 = 真实选题多轮实跑结果稳**，不是「Skill 读起来好 / 用户读完觉得写得好」。纸面好听但未实跑的条目**不进包**。
- **先实跑，再写入待定项**。筛查可先挂「可加 / 冲突跳过 / 待实跑」；待实跑项（如参考库项 3/6/7）未经真题稳定验证，不得升为硬规则。
- **增量只进对应小 Skill**；共享原则放 `references/`，入口只挂指针。定期合并同类补丁、删过时条文；禁止三处复制同一长段、禁止用「增补章节」堆屎山。
- **冲突裁决优先级**（与 design 包一致）：用户确认 > pipeline/checkpoints > 各 Skill 更早硬规则 > 参考包增量。冲突时以上者为准，不另立第二套哲学。

## 参考库冲突现象（一律跳过，不学不写）

从外部范文/参考包观察时，下列写法与本产线硬规则冲突，**一律跳过**：

- 升华尾 / 鸡汤 / 时代收束（「科技有温度」「我们必须…」）
- 点赞 / 转发 / 评论区 CTA、向读者布置任务或以发问收尾
- 「万字干货」类标题腔
- 无口径绩效数字墙当结论（可旁置口径，不吹成行业基准）
- 营销演讲稿、论文目录体当教程/资讯范文
- 文体串味（资讯写成观点、教程写成软广/行业评论等）

细则见各参考包 lessons（[design](design-article-ref-lessons.md)、[中文包](chinese-pack-lessons-2026-10-24.md)、[AI Skill 库](ai-skill-ref-library-2026-10-24-lessons.md)）。

## 改哪里

- 一条规则只写进**对应小 Skill**（字数→01/04/05；人味句式→14；配图→17；生图→18；图文流程→02/15）。
- 共享原则放 `references/`，入口只挂指针，禁止三处复制同一长段。
- 实跑翻车：先记「现象 → 建议改哪一文件哪一节 → 一条硬规则或反例」，用户点头再改（或用户已授权「按实跑稳了再写」时，稳后再写入）。

## 不要做什么

- 不要为同一句话在 01/04/05/14 各贴一遍。
- 不要用「增补章节」代替合并：同类补丁收成一条，过时条目删掉。
- 不要把读者面正文写成维护说明；规格与元信息只留计划/项目说明。
- 不要一次大重构；优先薄补丁。
- 不要把烟测/正式稿整篇贴进 Skill。
- 不要改与本次无关的旧层（如未授权时的 02/15/18）。
