# 跨技能交接约定

交接已有材料和确认结果，避免下一步重猜。只取当前阶段需要的信息；未知项说明影响，不为填字段编造事实。一般交接直接留在对话或正式稿件中；用户实际认可的版本按 [认可稿记录](checkpoints.md#认可稿记录) 维护到内容项目现有说明中，不另建状态或交接回执。

| 信息 | 最小内容 |
|---|---|
| 当前任务 | 平台、长文/静态图文/短帖、本次交付范围和当前阶段 |
| 定位与材料 | 题目、Notion条目或指定原稿；用户选定、明确代选或待选状态；原始笔记/截图/来源、内容项目位置 |
| 事实边界 | 可核验事实、用户自述、观点、教学示例和未验证方案 |
| 确认结果 | 分别注明题目、大纲、文案、分页、总张数、标题和风格的真实状态；认可文件的精确版本、对应源、认可范围与记录位置；保留不可改内容，不把找到材料当作已选题 |
| 本阶段职责 | 交给下游做什么、应返回什么；只处理当前阶段 |
| 文案分工 | 发布标题、封面大字、发布正文、逐页文字和图注分开 |
| 制作规格 | 当前页或整组范围、像素比例、素材角色、系列基准与单页例外 |
| 恢复与检查 | 最新文字版本、最后交付页、下一页；作者自查与独立验收分别注明，含审阅者、实际版本、范围、结论和未核缺口 |
| 实际完成 | 已有文件或成图、仍为计划的部分、下一步可执行范围 |

小红书先交内容大纲供用户确认，再交完整主文案、标题、封面字及发布正文供用户审阅，确认后才正式分页。大纲可预估张数与容量，文案按逻辑段落组织，不提前交正式P1/P2。分页交逐页职责、核心观点、完整图内文字、必要素材与关系类型，总张数明确包含封面；提交前复核新增或调整的文字。

分页从认可文案分配，不擅自改主张或删重要条件；需要改变已确认内容时回相应确认点。已有页序或指定单页沿用，不重走已完成阶段。内容节点定页序，制作节点核容量；不因下游参考的推荐页数自行扩张。

交给 [独立验收](pipeline-contract.md#作者自查与独立验收) 时提供需求、原始依据、认可范围及当前实际成品；不只交作者的完成声明。审核仅列问题，改稿仍由作者按授权执行，独立通过不等于用户认可。

长文配图给出插入段落、解释任务、图种、完整文字、图注、来源和尺寸。先确认执行关系再画流程；并列概念或资料来源不画成必然顺序。

“下一张”先读取本项目的当前认可版本记录，核对页序、最后交付页与系列基准；沿用本组认可的基准，而非最近一张局部例外。记录不足时只补问具体页序、版本或基准，不按文件时间猜、不重新选题。内容与视觉变更后的检查复用见 [阶段分工](pipeline-contract.md)。

01 长文与 04 教程的成稿位置遵循 [总入口的 Notion 优先与本地兜底规则](../SKILL.md#保存与交付)；交接实际 Notion 页面与周次，或无法连接的具体原因及本地成稿位置。图片制作工作文件、小红书图文和短帖仍沿用当前内容项目（X 短帖不落盘，见 03）。图文分开制作时保持插入位置对应，不能把图片占位写成已经成图或已嵌入。
