## 硬规则（先于成稿）

1. **未定来源，不写主张；调研清楚再写。** 大纲与文案前先按类型选定主来源并实际读取；不能先上网拼通稿再倒推「好像讲过」。过程文件存放见下文。
2. **点子对齐用户。** 说的点须对齐用户已有点子、课上观点、笔记主张或本次明确交代的切口；网上材料只做核事实与取真素材，**不当主张来源**。
3. **禁止通稿科普腔。** 禁止把随便搜到的网文、媒体综述、竞品软广改写成「普通科普」顶替用户观点。
4. **缺本地材料不编。** 缺课上/知识库材料时：问用户要路径或标缺口；**禁止编造「老师说过」「笔记里有」**。
5. **价格/额度**：小红书图文**一律不写**具体价格与额度数字（写死也不行）；禁止「以官网为准」类甩锅。详见 15「价格与额度」。资讯入口（05）可核官网写清并旁置日期。

## 类型 → 来源优先级

| 图文类型 | 主来源（先读） | 辅证（可后） | 网上检索只做 |
|---|---|---|---|
| **知识点 / 方法 / 课上概念** | 用户本地知识库、课程笔记、老师材料（如 Obsidian、课堂记录、用户指定路径） | 官方文档、原始论文，仅核术语/版本是否过时 | 核事实、补定义边界；**不**当主张与例子来源 |
| **产品 / 工具介绍** | 官网、官方文档、官方 GitHub / 应用商店页 | 一手实测（须区分演示 vs 可复现）、可信评测 | 核版本/定价/功能是否仍在；取 Logo/截图等真素材（见 cover-by-genre） |
| **攻略 / 资讯 / 事件** | 当事方公告、原始报道、可核时间线 | 用户笔记里的判断（若有） | 交叉核日期与数字；不把转载通稿当独家主张 |

未点名类型时：先判断偏知识点、产品还是攻略资讯，再选上表一行。合集类按条分别定来源，不整组共用一篇通稿。

## 点子对齐（执行检查）

写大纲或文案时自问：

- 这一句主张，用户材料里**有没有对应点**？（有 → 用用户的说法/角度；无 → 标缺口或降格为「待核实」，不装成已有观点）
- 例子与取舍，是用户课上/笔记里的，还是网上顺手抄的？（后者默认不用，除非用户明确要外部例且标明出处）
- 若只读得到官方功能列表、读不到用户切口 → **先问用户要点子或笔记**，不自行扩成「十个必会技巧」式通稿。


## 调研过程文件（存放）

- **不随便落本地**：检索草稿、整页另存、大段网页镜像、临时「调研.md」等过程文件，默认不写入用户磁盘散落路径（Downloads、桌面、文章库根目录等）。
- **交付只留干净结果**：可核来源链接、必要短摘录、事实表可进对话或题目项目约定目录；用完即删过程稿，或只放用户当场指定的项目文件夹。
- **禁止**为「好像调研过」批量下载官网/仓库全文到本地当素材库。
