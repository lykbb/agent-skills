# 小红书图文生成

> **执行顺序以 [02 图文入口](../02-图文-xiaohongshu-post/SKILL.md) 为准**：内容大纲→完整文案→正式分页→（确认后）18 生图；本文件提供分页与图内文字方法，不自行重启整条产线，也不经过 17。

## 按当前阶段推进

先判断用户要选题、框架、文案、图片还是局部改稿；已确认的内容直接沿用，不重复走完流程。用户提供的最新改稿或截图优先于旧稿；提取特点时区分作者补充的事实、表达偏好和一次性布局，不把截屏未显示的部分视为主动删除。

1. 选题：给少量具体切口和推荐理由；已定题就直接沿用。
2. 核验材料：读取笔记、项目或原文，分清已有事实、教学示例和待核实说法。大纲/文案前先按类型定主来源（见 [先找来源再写点](references/source-first.md)）：知识点优先本地课/知识库，产品/工具先官网·文档·GitHub；网上只核事实与取真素材，主张对齐用户点子，禁止通稿科普腔。
3. 分页框架：先说清每页放什么、总张数及页面职责；按用户给定张数安排，不为套模板扩页。
4. 文案：区分发布正文与图内文字；按要求交付可用文字，生图前做人味复核。
5. 模板与试稿：在内容范围明确后选风格；需要试效果时先做一张，认可后沿用。模板入口见[模板路由](references/guizang-template-routing.md)。
6. 逐页制作：按指定单张或明确授权的整组范围生成；“下一张”只推进一页，不代表制作余下全部页面。
7. 校对成稿：检查内容、排版和实际尺寸，交付对应图片；整组出齐时再核对覆盖、顺序和风格一致。

这些阶段用于判断当前要做什么，不是每次必须从头执行的审批流程。已有框架、确认稿或选定模板时跳过已完成阶段；用户明确要求出某张时，在既定范围内直接制作。只讨论分页或模板、以及“先别生图”，都不构成出图授权。用户说“第二张”“下一个”时，按已确定的顺序生成对应页，不重复确认题材和风格；顺序不明确时再问。用户要一张静态图时交付完整图片，不用交互组件替代。只要文案或框架时，不自动出图、创建网页或启动制作工程。

所有图文成稿，包括标题、封面和图内文字，交付或生成图片前默认用 [writing-skill（人味 Skill）](../14-正文写作-writing-skill/SKILL.md) 做一轮自然表达与内容保护复核。保持已确认的观点、限定、页序和篇幅，只处理当前授权部分；润色不重跑已完成的框架流程，也不扩大图片制作范围。

## 从材料里选题

- 优先读取用户最近笔记、相关课程记录和已有选题，再补公开来源。需要确认课堂原意时回到原始记录，清洗稿仅用于定位；疑似转写错误另行核验。未找到材料不能据此断言老师没讲过，外部补充和自己的推演不能写成课堂原意。
- 从实际问题、任务、使用卡点、决策取舍或有材料支持的观点切入，说明读者能理解什么、解决什么。保留经核实的关键分支和条件，避免仅换术语复述课堂内容；公开文案直接讲知识，不默认加入“老师说”。
- 选题切口**可选**「对象 × 动作 × 读者收益」；不强制情绪站队，不强制评论钩子。学爆款只学信息顺序，不抄词、不灌词库。
- 选题或产品拆解时提供有区别的切口，不机械套五层框架。用户已选题时围绕该题推进，不另换案例、产品或主线。
- 用户要求“比较新”时，区分旧概念、近期论文、机制和产品更新；核实新在哪里及来源日期，不把仓库更新直接写成概念首创。
- 用户未实际体验的工具写成资料介绍或待体验选题，不写成亲测。热点和高互动方向只能作为候选，不能承诺“必爆”或未经验证的效果数字。

## 内容与素材真实性

- **先找来源再写点（硬）**：未定来源不写主张。类型→来源优先级与点子对齐见 [source-first](references/source-first.md)。知识点/方法优先本地知识库与课上材料；产品/工具先官网·官方文档·GitHub；网上检索=核事实与取真素材，不当主张来源；缺本地材料则问用户或标缺口，不编「老师说过」。
- 技术内容优先用户已核实材料、官方文档和一手研究；版本、功能、价格等动态信息在使用时核验。把已验证事实、厂商说法、自己的推断和未知部分分清，不将方案写成实际运行结果。
- 原图、真实截图、风格参考与生成示意分清角色。真实界面不重新生成后声称原样截图；AI 生成的功能场景注明“设计场景示意”等必要状态。
- 截图保留有讲解价值的内容，遮挡需保护的信息。标题、来源标签和资料分享都必须有对应材料；不能为了真实感添加无依据的“内部规范”“面试真题”“官方认证”。
- **联网取真素材（硬）**：封面或内容页要用官网 Logo、关键截图、仓库示意图或界面专有文案时，**必须先调研联网**取可核材料，再排版；禁止凭空画假 UI / 假标签 / 假 star / 假认证。细则见 [类型→封面与真素材](references/cover-by-genre.md)。
- **真标签**：菜单名、按钮文案、专有控件名须来自实截或官方材料；无材料不编「看起来真」的假 UI 字。
- **证据页**：讲具体产品 / 仓库 / 后台操作时，整组至少 1 页能证明见过真东西（真界面截或 Logo+名干净页即可）；**不是**默认贴官例全景+说明字。纯观点 / 方法页允许纯文本卡；未要求配图不加演示大图。
- 引用和核验说明按实际用途放置；可在聊天或正文交代的内容，不强行塞成图片上的小字或重复页脚。

## 价格与额度（小红书硬规则）

- **一律不写**具体价格、套餐价、每月 credits/额度、名额上限等数字（平台易判引流/软广）；**写死核准数字也不行**。
- 禁止「以官网/定价页为准」「额度细节以官方页面为准」等甩锅句；需要导向官网时只用产品能力/用法叙述，不夹带价与额度。
- **资讯·调研（05）例外**：公众号资讯可核官网写清价格/额度并旁置核验日期；本规则约束 **02/15 小红书图文**，不削弱 05。

## 默认视觉与封面

优先沿用用户当前选定的风格。未选定时，可参考 Lovart、Skywork、Pi Agent 的干净层级，或按[模板路由](references/guizang-template-routing.md)选用完整的 Guizang 版式；不把某次选定的配色固定为所有任务的默认。卡片/信息图风仍可用。

- **类型→封面**（细则 [cover-by-genre](references/cover-by-genre.md)）：**产品/工具介绍** → 产品名 + 可见官 Logo/关键元素 + 一句话用途（名与 Logo 可居中作主角）；**可选**少字骨架「名大字 / 一句品类 / Logo 居中 / 一句主张」（见 [CASE](../references/visual-cases/xhs-first-gen-clutter/CASE.md)，非全站默认）；本品类避坑：刊头+多层标题堆；**攻略/资讯** → 问题或收益标题主导，真截/官图作证据拼贴、少大 Logo 墙；**工具知识点/方法** → 概念关系或步骤为主视觉，可用官仓示意图**抽象**（去底、简化节点；正例口径：LLM Wiki 知识图谱抽象封面），不整页 README 糊上。
- 未指定时可用暖白或米白背景、黑色主文字和少量主题色。选择杂志风时保留相应纸质层次；选择 Swiss 时按其平面、无衬线和单一强调色规则处理，不把纸纹、阴影强加到每种风格。
- 封面先突出一个中文主题、具体问题或清楚的阅读收益，主标题在手机缩略图中可辨认。用字重、尺度、位置和图文关系建立吸引力，不靠堆满装饰。**封面大字只押一个信息点**（防多层标题堆；见 [16](../16-标题封面字-title-creator/SKILL.md)）。
- 对比题可用红绿等反差色表达真实差异，作为可选方案；保留暖白纸质和克制配色的默认方向。颜色应辅助信息分组，不制造没有材料支持的对立。
- 标题应有字形设计和力量感。用户指定优设等字体时先查已有字体；实际排版可加载字体，生图可使用真实字体样张作字形参考。不能把参考字形说成实际嵌入该字体，不能擅自安装字体。
- **拉丁字母字距（硬）**：封面/分页品牌英文与拉丁大字，字母不得重叠或糊成一团；详见 [18 拉丁字母字距](../18-生图制作-social-image-studio/SKILL.md#拉丁字母字距成图硬闸用户已确认)。字号仍服从 pipeline 默认可覆盖，本条只管字距。
- **官网图可弃（审美）**：**未要求就不加图**；不一定非要放官网示例/演示大图。官图不好看或不适合版式就别硬塞，改产品名+Logo、抽象界面或干净排版。禁成图「官方生成示例」角标与图下解说（见 18）。取真规则不变（见 [cover-by-genre](references/cover-by-genre.md)）。
- **字多乱排（硬）**：首批成图若字太多、排列乱、拉丁挤叠/中文残笔重影/底栏裁切/层级糊成一团 → 失败重出，**不得定风格**；见 [反面 CASE](../references/visual-cases/xhs-first-gen-clutter/CASE.md)。
- 图标按可见形状的视觉重心居中，统一可视尺度、上下留白和标签基线，不仅对齐外框。竖版流程按阅读顺序重新组织，不把宽横图硬缩成小字。
- 同组图片统一尺寸、边距、标题层级和必要标记。小红书静态图默认 3:4；**新系列制作尺寸以 02 / pipeline 为准：1080×1440**（旧文 1086×1448 仅历史参考，不得覆盖已确认规格）；用户指定比例优先，跨平台不机械沿用。
- 避免大黑块、廉价霓虹、重复装饰和无用途的小字。只保留确实说明来源、步骤或示意状态的角标，不自动添加日期、页码、系列号和口号。

## 按内容选择表达

### 软件介绍

单软件介绍默认一软件一张：名称与核实过的官方 Logo、中文定位、简短介绍和一个完整使用场景。简介通常约四行、50–90 字，直接说明用途、用法和关键特色；下部场景可配少量辅助卡片。先**联网**查官网核对软件身份、定位和功能，纠正名称混淆；Logo 优先使用官方素材作参考，不凭印象编造。封面规格对齐「产品/工具介绍」行（见 [cover-by-genre](references/cover-by-genre.md)）与 18 产品介绍句。不能把未验证的能力、成绩或承诺放进示意图。

### 来源与工具推荐合集

封面突出主题与阅读收益，分类内容页承担名称、官网素材和具体用途。制作信息源、工具清单等合集，或从用户改稿中提炼此类文案特点时，读取 [推荐合集的分类、封面与文案](references/curated-recommendations.md)；不套用单软件一张的版式。

### 教程与知识图文

组件总览、分组讲解、限制张数或多轮视觉反馈，读取[系列分页与改稿](references/series-and-revisions.md)。总览页列清分组与名称；没有执行关系时，不擅自改画流程图。
- **流程图页可选手绘草图风**（与长文同一风格 L）：白底粉彩、略抖线、圆角框；见 [hand-sketch-flowchart](../references/visual-cases/hand-sketch-flowchart/CASE.md)。**须竖版重排**为 3:4 / 1080×1440，禁止把长文横图硬缩；无执行关系仍不擅自画流程。

- 每页承担一个重点；根据内容选步骤、对比、循环、关系或案例，不套用软件海报的固定卡片数。
- 多概念封面用共同问题或中文主题统领，名称、角色和解释放进对应模块，不将多个英文名称堆成大标题；单概念介绍可用名称作主标题。
- 节点写清做什么、输入什么、输出什么；术语配落地解释，不堆抽象名词。操作教程用同一个问题贯穿效果、流程、关键配置和测试，主标题不挤占解释图的空间。
- 图示区分并列、顺序、条件分支、回路、资料供给和执行流。核心环节及可选环节不能混为一谈，新增节点要说明解决哪个问题。
- 用户要求 RAG 全流程时同时保留离线建库和在线问答，不擅自缩成某个客服案例。案例用于辅助讲解，不能改变已确认的内容范围。
- 未搭建或未测试的案例标明示意或教学性质；规则、权限、工具、重试上限及兜底按场景说明，不把框架支持写成自动完成。

### 个人观点与跨平台贴图

读取 [个人观点与封面设计补充](references/opinion-covers.md)。围绕用户真实观点、例子和疑虑组织内容，保持作者口吻；迁移平台时重新检查比例和裁切。

## 发布文案与互动

- 文案简短、具体、可扫读，按用户要求的篇幅交付。软件集合通常约 200–350 字，单软件更短；知识点和观点不强套“软件名｜用途”的结构。
- 开头尽快交代具体问题、场景或读者收益；正文分点解释关键内容，结尾按需要给一步能执行的建议，不强加哲理和金句。需要优化封面吸引力、正文排版或互动时，读取 [标题、开头与互动](references/hooks-and-interaction.md)。
- **Emoji（仅小红书，用户确认）**：发布文案与分页/封面字可**适度**加一点——点缀关键节点（如列表小标、轻量情绪点），不替代信息、不段段堆、不每行一个。公众号长文及其他入口（01/04/05）正文与封面默认不加。技能说明、代码、注释、制作记录不加。互动 CTA 仍禁（见 [pipeline](../references/pipeline-contract.md)）；emoji ≠ 评论召唤。
- **互动 CTA 仍禁**（见 [pipeline](../references/pipeline-contract.md)）：不加评论召唤、扣 1、任务式发问收尾。真实可分享资料可自然交代用途，不编造「领资料」承诺；hooks 参考不得覆盖本禁令。
- 不虚构亲测、效率提升、点赞率或评论率。少用“赋能”“颠覆”等空泛宣传，话题标签保留少量相关项。

## 生成、改稿与交付

图片制作阶段进入[独立图文生图工作台](../18-生图制作-social-image-studio/SKILL.md)，完整执行模板、背景、脚本、审查与成稿交付。本 Skill 继续负责原有选题、材料、框架和文案；只要文字时不启动生图。

用户明确要求当前图片后，先查看编辑目标或本组认可的系列基准图片（排除仅限单页的风格例外），标明各输入的角色；沿用已认可的配色、字形和边距，布局随内容调整。已选择 Guizang 或其他可编辑排版模板的文字卡片，优先修改模板并导出 PNG；按[模板路由](references/guizang-template-routing.md)读取对应资源。插画、纸艺封面及位图改图使用 imagegen 技能与内置生图工具；真实界面、字标和截图可用于可控排版。不得用重绘替代原图后声称原样保留。

局部文字改稿以最新获认可版本为目标，只改指定区域，保护其他文案、插图、位置、配色和画布尺寸；布局调整只改相关部分。用户给定标题时保留其主题和命名，不擅自换成另一句钩子；术语需统一时，只在本次授权页面内检查。改后对照输入图检查指定改动和其他区域是否漂移。用户说“太乱”时先重组信息层级和关系，不用更多装饰掩盖问题。

生成后检查文字、技术术语拼写、**拉丁/英文大字字距（不得字母重叠）**、图示关系、素材真实性、手机缩略图可读性、图标对齐及实际像素比例。按语义断行，避免英文词组被拆散、末行只剩一个字或标点；定义和例子不互相挤压。官网图审美不过关或未要求却硬塞官例/示例说明字则弃用重排（见上「官网图可弃」）。字多乱排则整张重出、不定风格（见上「字多乱排」）。严格 3:4 要核对实际宽高，不能只依据提示词声称达标。图片阶段按独立生图工作台完成全部适用审查与HTML校验；同一未变版本已通过的检查不重复运行，不逐轮反复追问是否检查。

最终 PNG 保存到当前项目对应目录，沿用既有结构并创建新版本；保留未授权删除的旧版。排版试算尽量在内存或当前页面中完成，不把每次微调都保存成一组候选文件；保留可继续编辑的源文件和实际交付图片。默认交付图片或下载链接及实际尺寸，不自动创建提示词、制作说明和检查记录的 Markdown 旁文件；用户需要提示词、源码或记录时再交付。不要重复讲制作过程。
