# Title Creator（起标题）

两套逻辑分开用，不要混：图文走「直接」，长文走「深度」。

共同底线：不托大、不搞工整对仗（与去 AI 味口径一致）；标题承诺的东西正文必须兑现；卖点和观点必须经得起追问，不拿品类共性凑数。

**抓眼层（用户确认，可兑现之上）**：先过兑现与换名测试；之上允许有限抓眼球——对比、反差、具体结果、场景痛点。禁止空钩子、假数字、未兑现承诺、评论区召唤。价格/额度硬禁见 15；互动 CTA 禁令见 [pipeline](../references/pipeline-contract.md)。学爆款只学信息顺序，不抄词、不灌标题库。

**封面大字**：只押一个信息点（防刊头多层标题堆）；类型封面见 15 / [cover-by-genre](../15-小红书分页-xiaohongshu-image-posts/references/cover-by-genre.md)。

## 一、图文标题（小红书等）：直接、新闻、一眼懂

图文在信息流里抢的是第一眼。核心认知：好标题不是想出来的，是从事实里挑出来的。

三条铁律：

1. **简单直给优先**：太花里胡哨的标题读者其实不爱看；太素也不行。直给为底，最多加一个具体细节（场景、数字、独有动作）。
2. **新闻本身就是标题**：先问这件事本身够不够劲——大厂下场、第一次、新玩家入场这类事实，直接用「主体 + 也 / 开始 / 出了 + 做的事」成题，不用再替它找卖点。例：《Anthropic也开始做个人Agent了》。
3. **卖点必须是独有的**：自检法是换名测试——把标题里的产品名换成任意同类产品，标题还成立，这就是品类共性，毙。例：「会干活」「不用你开口 / 会主动找你」是所有 personal agent 的标配，写进标题等于没写。

流程：列事实三件套（主体是谁 / 发生了什么事 / 它独有的一点，独有 = 换个产品就不成立）→ 按优先级出候选（事实直给 > 独有卖点 > 具体场景；可兑现上可叠抓眼层）→ 自检（换名测试、≤20 字、读者视角、第一眼能懂）→ 只给 3 个以内候选并明确推荐一个。候选**可选**旁注一行「角度类（结果/痛点/对比/清单等，不强制凑满）+ 正文哪段兑现」；不附标题库。两轮被毙就停手，把话筒递回用户，请他给关键词或半句话，围着他的原话修，不另起炉灶，也不要把他的原话包装成自己的功劳。

## 二、长文标题（公众号等）：深度

长文读者是打算读完的，标题要让他觉得这篇有东西。长文标题/封面字**不加 emoji**（小红书 emoji 见 15）。

1. **标题装判断，不装悬念**：把文章最核心的判断或洞察放进标题，读者点开是为了验证和展开它。不用问号钩子，不用悬念断句骗点击。
2. **可以稍有文气**：公众号标题可以浪漫一点、有点韵味，但文气服务于判断，平实的判断句优于漂亮的空话。
3. **深度自检**：这个标题换到另一篇同主题文章上还成立吗？成立，说明没抓住本文独有的东西，重来。本文独有的框架、概念、结论，才是标题该装的。
4. **长度可放宽**，不必卡 20 字，但一句说完，不叠两个分句抢戏。

## 设计文章参考增量（2026-10-24）

共享原则见 [design-article-ref-lessons](../references/design-article-ref-lessons.md)。例子库仅追加风格说明，不灌水。

- 长文标题可 **主判断/主对象 + 范围副信息**：副信息装协作/体验/美学等边界，不装悬念问号。
- **过程型**「从 A 到 B 的 N 件关键事」仅当 N 真是过程阶段且正文兑现，不作干货通胀。
- **封面文案层**：短调性句（可无）→ 主标题 → 范围副题；主标题少而稳，主体居中防裁切。
- **慎用**「万字干货」「诚意之作」腔——不进好例（见例子库坏例一句）。
