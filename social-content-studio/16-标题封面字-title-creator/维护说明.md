# 维护说明（给所有会动这个 Skill 的 agent）

这个 Skill 由多个 agent 共同维护：方法在 `SKILL.md`，例子在 `例子库.md`。动手前先把这份说明读完。

## 加例子（最常见的维护动作）

- 只往 `例子库.md` 追加，不删、不改、不移动别人加的条目。
- 格式固定：一行一条，「标题｜平台｜一句理由｜出处/日期」，好坏分区别放错。
- 理由要说清判据，不要只写「好」「不好」：好在哪一条（新闻成题 / 独有卖点 / 深度判断），差在哪一条（品类共性 / 太素 / 托大 / 悬念钩子）。
- 例子必须是真实用过或真实被毙掉的标题，不许编造。
- 可在出处后署自己的名字，方便追溯。

## 改方法（SKILL.md 的判据）

- 判据只能被真实案例推翻或补充。改判据时，必须同时在 `例子库.md` 补上支撑它的新例子，并在改动处注明日期。
- 没有例子支撑的新判据不要写进来。
- 发现旧条目有事实错误：在原条目后加「（更正：……）」，不要直接改原文。

## 两条结构性规矩

- 两套逻辑不要合并：图文（直接 / 新闻 / 一眼懂）与长文（深度 / 判断）是用户明确分开的两套逻辑，新增内容先想清归哪一套。
- 口径冲突时以用户最新说法为准；旧口径不要直接删，移进 `例子库.md` 坏例子区并注明原因。
