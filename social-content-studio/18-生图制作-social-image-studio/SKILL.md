# 图文生图工作台

这是独立、完整的生图 Skill；模板、背景、参考和脚本都在本目录，不依赖原 Guizang Skill 目录。原来的选题、文案与写作能力继续正常使用。来源和授权见[来源说明](references/upstream-source.md)与根目录 LICENSE。

## 平台风格分流

- **小红书静态图文**：卡片/瑞士网格等信息图风格可用。
- **公众号长文（写实为主）**：优先真实场景摄影感画面，**场景多样、忌书桌套娃**；禁止暗代码墙当主图；压字无把握则不配字。白底PPT式卡片每篇最多1–2张；封面默认单张横图交付，不做双封面并排重复文案。



## 公众号写实质量闸门（用户已确认）

- 写实 ≠ 书桌套娃：同篇场景多样化（窗边/城市、通勤、书架、实验室、户外等），不要张张电脑桌/笔本。
- **禁止把暗代码墙当主图**；过暗、无视觉重点、看不出表达意图的图不得交付。
- **排版没把握就不要压字**：宁可不配字，只交干净摄影感图；观点留给正文图注。禁止字丑、字挤、硬贴标题。
- 小红书静态图文仍可用卡片风；本闸门主要约束公众号长文写实插图与封面。

## 读者面文案禁区（长文/图文通用）

成图上禁止出现制作元信息：画幅比例标注、像素、平台说明、字数目标、「依据流程/公开材料处理」等。一并禁止默认上图的**示例/来源角标**：如「官方生成示例」「—— Xxx 官方生成示例 · 场景名」、图下横线解说、绿框/色框长解说、「World Labs / 官网出品」式页脚广告角标（除非用户当场要求引用该条证据）。只保留读者需要的标题与观点文案；规格与来源说明写在交接计划/聊天里，不塞进成图。

## 拉丁字母字距（成图硬闸，用户已确认）

**小红书硬约束**；公众号长文若封面/图内有英文品牌名或拉丁大字，**同样建议**按本条验收（不改中文正文行距规则）。

- 封面与分页上的拉丁字母、品牌英文名：**字母之间不得重叠、不得糊成一团**；字距须一眼可读。反例口径：白底大字「Marble」中 a/r 笔画粘连、左缘裁切残笔 → **判失败重出**。
- 生图 prompt / HTML 排版须禁止 letter crowding、overlapping glyphs；必要时略增 tracking / letter-spacing，或缩短英文词、语义换行、略减字号换空间——**优先保证字距可读**，不为撑满版心把字挤死。
- 字号阶梯仍按 pipeline：**默认参考、可覆盖**；本条只管字距/防重叠，不把 96/68 等锁死。
- 目检列入交付前必查；HTML 卡走 qa-checklist 对应项。细则指针见 [qa-checklist](references/qa-checklist.md)。

## 官方素材可弃（审美，用户已确认）

**取真 ≠ 必须塞一张官网图。未要求就不加图。** 小红书硬；长文贴官图时同样建议。

- 选题/大纲/用户**未要求**配官网示例、产品演示大图、双图对照时：**不要默认塞**；少字排版页、Logo+名+一句主张即可。
- 官网首页、营销长图、整页 README、「官方生成示例」全景等若不好看或不适合版式：**不要硬塞**；宁可用产品名 + 官 Logo、抽象界面元素、干净排版页或留白。
- **双图对照 / 全景官例**仅当论证需要（如「同空间换机位」）且用户或大纲点名时才用；否则判过度装饰 → 返修删图留字或改抽象。
- 需要真标签 / 真界面文案 / 可辨 Logo 时仍须联网取真（见 [15 cover-by-genre](../15-小红书分页-xiaohongshu-image-posts/references/cover-by-genre.md)）；取到后可选用、可弃用——审美不过关就弃；**仍禁止假 UI 冒充**。图上禁「官方生成示例」类说明字（见上「读者面文案禁区」）。反面症状见 [xhs-first-gen-clutter](../references/visual-cases/xhs-first-gen-clutter/CASE.md)。

## 字多乱排（首张硬闸，用户已确认）

用户标注的「第一次生成」反面：**太乱、文字太多、排列很差** → 判失败重出，**不得拿来定风格**。症状与对照见 [xhs-first-gen-clutter](../references/visual-cases/xhs-first-gen-clutter/CASE.md)（其中「名大字/…/一句主张」仅为**产品/工具介绍可选**骨架，非全站默认；「刊头+多层标题堆」为产品介绍避坑）。与拉丁字距、官图可弃同查；不锁字号阶梯。

## 执行原则

- 以下十个环节都要检查。已有确认直接沿用，不要求用户重答；不适用的素材分支判断后不启动，不把“不适用”变成机制缺失。原型、截图、实况照片等分支完整保留。
- 当前用户的标题、文案、总张数、指定页、尺寸、系列基准与明确修改范围优先。只要“每页放什么”或“先别生图”时停留在讨论，不创建制作工程。用户说“下一张”只授权当前页序的一张。
- 本文件和[制作与审查](references/workflow-and-review.md)是本工作台执行规则；[完整上游机制](references/production-manual.md)保留所有原始分支供查阅。上游的默认张数、尺寸、local-tests 目录、逐页询问检查和素材署名建议，不覆盖用户约定。
- 不安装字体、浏览器或依赖，不自动上传稿件、购买素材或发布。先检查现有环境；缺项说明具体限制，不把代码存在说成实际跑通。
- 产品介绍封面应在主视觉中呈现完整产品名、对应的官方 Logo 和中文用途，让名称、主标题与图标形成整体；不能只靠角落小字说明介绍对象。按实际可见主体和手机缩略图判断 Logo 大小；Logo 须联网取自官源（见系列分页与改稿及 [15 cover-by-genre](../15-小红书分页-xiaohongshu-image-posts/references/cover-by-genre.md)）。
- 配色遵循用户当前偏好：蓝色不作为默认，只有明确匹配主题或用户指定时选用；已认可系列继续沿用其配色，不把某组的米白、陶土橙或其他颜色固定到所有主题。

## 十个环节

1. **接收范围。** 明确平台、图片类型、总张数、当前页和已有确认；读取[平台规格](references/platform-specs.md)与必要的[分类适配](references/category-cookbook.md)。纯文字知识卡可直接排版，不强行补无关照片；确需素材且未提供时，一次说明原图、找图或AI素材选项。
2. **核对材料。** 分清用户原稿、项目事实、官方材料、示例与生成场景。真实截图不重绘冒充原图；技术能力保留模拟/真实、状态/验证等限定。缺少关键事实就核实，不靠装饰补证据。
3. **确认页序和文字。** 依据[内容规划](references/content-planning.md)和[系列分页与改稿](references/series-and-revisions.md)确定页面职责。总览列清名称，不擅自改成执行流。图内文字按 [writing-skill](../14-正文写作-writing-skill/SKILL.md) 做人味与内容保护复核；原内容Skill继续负责选题与长正文，已确认稿不重写。
4. **选择模板和视觉系统。** 公众号封面按[视觉风格表](../references/wechat-visual-style-menu.md)选型，正文保持写实混搭；白底 Swiss/信息卡每篇最多1–2张。小红书静态图文可用完整卡片配方。使用[版式库](references/layout-recipes.md)完整的 M01–M16、S01–S12，共28种配方；结合[风格](references/style-system.md)、[主题](references/theme-presets.md)、[组件](references/components.md)、[竖版填充](references/portrait-fill.md)。需要试效果先做一张。单页换风格不改变整组基准；明确要求整组换风格才设新基准。
5. **准备素材、背景与组件。** 按下方分支表处理真实素材、照片叠字、地图、背景、图标和跨平台封面。检查来源与必要署名、主体裁切、字体和图片加载，不编造数据、日期、徽章或来源。装饰服务于层级和分区。
6. **落实可编辑源和依赖。** 从 assets 中对应种子复制到项目，已有同组源就复用认可版本。检查实际使用的背景脚本、纹理、字体、图标和相对路径；不要只复制空HTML。详见[渲染环境与脚本](references/rendering-environment.md)。产物放对应项目，绝不放 Skill 根目录。
7. **制作并导出。** 文字卡片编辑HTML/CSS并使用 `scripts/render-social-card.mjs` 导出；插画与位图修改用 imagegen。检查实际宽高、透明状态和加载结果。实况照片必须先确认静态首帧，再渲染、配对元数据与打包，不能省略为一张假动图。
8. **执行审查。** 每页做文字事实、人味、素材真实性、来源隐私、视觉层级、字体、**拉丁字距（不得字母重叠）**、裁切、缩略图与实际尺寸审查；HTML页面执行根目录 `validate-social-deck.mjs` 的R1–R9。同一未变版本已通过的检查不重跑，不逐页追加“要不要检查”的确认。自动检查不代替事实和目检，风格/密度提示不能靠假信息解决。发布风险按 [check-social-content-compliance](../19-发布复核-check-social-content-compliance/SKILL.md) 做适用复核；不承诺必过审。
9. **按反馈修改。** 保持系列基准，只改指定区域；整张改标题也保护其余素材和排版。先测量溢出再局部调整，按语义断行，避免孤字或拆开英文词组；只复核受改动影响的检查。详见[系列分页与改稿](references/series-and-revisions.md)。
10. **交付成稿。** 只交本次授权页面，显示图片绝对路径并简述实际尺寸；整组完成再核对覆盖、顺序和一致性。保留最终可编辑源与图片，不保存每次试算、核对回执和重复报告。清理旧文件前列精确清单等确认，用废纸篓。实况照片另报告实际验证过的包、时长和导入状态，不把未测的iPhone播放说成已成功。

## 长文参考审美闸门（对齐 17 图种菜单 + 设计文章增量）

共享原则与冲突裁决见 [design-article-ref-lessons](../references/design-article-ref-lessons.md)。本闸门为**单一清单**，勿与旧分段各读一半：

- 叙事插画可学暖色、纸艺/编辑感构图；**禁止**伪字、乱码、拼写伪影。
- 流程/关系/分栏图：先用 `diagram-design` 设计（用户确认 2026-10-27，见 17「制作、检查与交付」），不用通用生图直接画；中文清晰、手机可读；过密则拆图；**禁止** Mermaid/工具整窗截图当终稿，交付干净导出图。说明用流程可选手绘草图风 L（[CASE](../references/visual-cases/hand-sketch-flowchart/CASE.md)）；长文横幅、小红书竖版重排。
- 界面拼贴只用真实截图或明确标注的示意；不生成假产品 UI 冒充原图。
- 封面选型统一见[视觉风格表](../references/wechat-visual-style-menu.md)，按本题承接 17 的选择；仍默认只交一张主横封面。
- **图内字对比度自检**：字与底对比不足则加大对比、换位或去字，不硬贴。
- **排版样张**（字号/留白示意）勿当正文插图交付。
- 产品说明图可对齐品牌主色，但 **禁未授权扒素材商用**；无授权则用自有生成/示意并标注。

## 公众号风格标签（承接 17）

17 计划行若带 `风格=A…G` 或 `L`，生图须遵守标签语义；见 [wechat-visual-style-menu](../references/wechat-visual-style-menu.md)。L=手绘草图流程（可用说明图，非禁用）。  
计划写 `不做=H/I/J/K` 时，禁止潮玩卡通岛、落地页多图标英雄拼贴、怪纹理主画面、动漫主视觉（选题本身是漫除外）。

若 17 给出 `风格参考=visual-good-examples/…`，对齐该图的光色、层次与完成度；仍服从计划用途与绑图对象，不抄伪字。
