# 简历模板搜索与筛选

规则版本：v1.1.0。默认阶段：30—40 个候选的小规模试运行，人工验收后再决定扩围。

供 resume-writing 主 Skill 按需读取，也可独立交给找图 bot。用户要求“找简历模板、找版式、找参考图”时，按本文件搜索和筛选；仅修改标准或写简历正文时，不自动搜图。

## 1. 用途与优先级

沿用主任务中已明确的内容丰富度、语言、页数、设计工具和偏好。参考模板不限行业或岗位，不限定为 AI 产品经理；重点看其版式、美观度和替换真实内容后的承载空间。参考中的栏目名称、数量和内容不必与用户一致，也不要求它已经有项目实践或自我评价。

**清晰易读 ≥ 专业可信 ＞ 视觉精致 ＞ 个性表达。**

- 优先让招聘方看清最终填入的真实经历；可以将其他行业的栏目、A／B／C／D 占位标题替换成简介、工作、项目等内容。改标题、换文字、合理拆分或合并大模块属于正常复用，不因原文主题不同而淘汰。
- 避开花哨装饰挤压正文的结构。重点排除连续大量零碎无关指标、又难以替换成用户真实内容的模板，例如连续超过 5 条体脂、体重、BMI、血糖等独立指标。大模块数量与零碎指标数量分开判断，不把 6 个可替换栏目当作 6 个无关指标；具体判法见 C。
- 专业可信指信息呈现规范、归属清楚，不能仅凭模板判断示例人物的经历是否真实，也不把模板作者的名气当质量证据。
- 评价简历正文，不把宣传海报外部的渐变背景、纸张叠放和投影算作正文设计。渐变、纹理、头像或双栏本身不加分也不扣分，看其是否服务阅读。
- 质量分用于筛选，个人喜好用于选择。高分不等于用户喜欢；不虚构“审美匹配分”，不给 ATS 得分或录用概率。

### 地区目标与搜索自由度

- 正式推荐 10—20 套去重高质量作品，目标中国大陆 60%、其他国家及地区 40%；10 套约为 6／4，20 套约为 12／8，不要求单批精确满足。搜索规模与正式推荐数量分开，按下方试运行参数执行。多页、换色、转载及同时进入两个用途库都只计一个作品 ID。
- 地区按模板主要面向的招聘市场、设计内容及来源说明判断，不简单按网站所在地、作者国籍或文字语言归类。依据不足标“地区待确认”，单列并暂不计入两地名额。
- 不限制职业、行业或设计风格，可参考产品、设计、工程、金融、咨询、建筑等方向。现代、简洁、精致、高级、专业可作为检索方向，评价仍落实到可观察的设计；自主扩展关键词，推荐遵守用户已明确的偏好。
- 国内、海外使用相同的五维权重与通过条件，分别筛选 S ≥ 4.0 且符合各项下限的作品。某地区不足时可以少提交，报告目标数、实际数及缺口，不降低门槛或重复计数凑比例。
- 国内方向重点检查中文排版、信息组织与正式求职场景；海外方向也可借鉴视觉设计。按第 5 节分别判断“视觉灵感”和“实用模板候选”，可以双标签；不因尚未适配国内投递而抹掉视觉价值，也不把漂亮图片称为已可直接使用的母版。
- 保持版式多样性，避免高度相似的作品反复出现。同一模板跨站转载、换色或裁切只计一套；兼容两地时按主要市场计一次，可注明兼容其他市场，不能在国内与海外重复占位。

### 小规模试运行与扩围条件

当前默认先运行 30—40 个候选的完整小规模试验，经过人工验收再决定扩围，不直接执行此前的大规模计划。

| 阶段 | 当前试运行目标 | 计数口径 |
| --- | --- | --- |
| 搜索发现 | 30—40 个候选作品记录 | 有具体作品或来源链接，不是查询次数或网页缩略图总数 |
| 去重看图评测 | 评测其中实际可查看的不同作品，记录真实数量 | 打开完整清晰正文、写出五维证据；本阶段不要求至少 50 个 |
| 正式推荐 | 原目标 10—20 个，质量不足可少交 | S ≥ 4.0 并满足相应用途门槛，不能为凑数提高搜索预算或降低标准 |
| 精选 Bad Case | 约 5 个，有实际证据才收录 | 差例或误判，不计正式推荐数 |
| 特别发现 | 最多 2 个 | 单列局部价值，不计正式推荐数或地区配额 |

- 不因找到 10 个合格作品就提前结束，也不强求收满 20 个；按 30—40 的发现计划完成去重、实际看图、评分、交付、人工反馈与复盘。受访问或图像限制无法完成时，报告实际数量和原因。
- 人工验收前标“待验收”，不能把 Bot 已交付称为全流程验证通过。用户反馈后的复盘记录误判、可用结果、耗时、可核实费用和发现率。
- 首轮试运行完成并经人工验收后，由用户决定是否扩围。此前 80—100 条发现、尽量至少 50 个实际评测仅作为第二阶段参考；100 个以上须另定明确预算和停止条件，不自动扩大。
- 不因配额、热度或发现率影响单张作品分数。地区 60:40 是筛选合格者之后的组合目标。
- 记录发现数、去重数、实际看图数、完成评测数、待检查数、各用途合格数、最终推荐数、地区分布与耗时。发现率用“达到相应正式门槛的唯一作品数 ÷ 完成评测的唯一作品数”；无可靠计费数据写“费用未获取”，分母为 0 写不可计算。
- 本轮参数属于试验方案，依据实际反馈再修改。不为了一个案例不断增加规则；先检查原规则是否执行，再决定保留、澄清或删并重复要求。

## 3. 三个门槛

先看版式是否有可替换文字、可容纳段落的结构，再检查证据是否足够。其他行业、不同栏目或占位文字均可进入评分；不要因示例主题无关就提前排除。若页面主要依赖难以替换的独立指标和图表，按 C 判断，而不是用主题或关键词直接否决。

| 门槛 | 通过条件 | 不满足时 |
| --- | --- | --- |
| 完整正文页 | 至少能看到一张完整简历正文页，页面内容没有被裁掉或其他纸张遮挡；位于较大展示图内也可以，只要能看清 | 查找完整页；仍找不到则待核实，不进入推荐 |
| 足以判断的清晰度 | 正面或近似正面，能辨认正文及已有的辅助信息、线条等，无严重模糊、倾斜或遮挡；不要求一定有日期或图标 | 找清晰原图；不凭缩略图猜测版式细节 |
| 可追溯来源 | 有可查看的来源页或原图链接，并已实际查看该图 | 只有搜索摘要、标题或失效链接时不评分、不推荐 |

必须真正打开并查看图片，不能用搜索标题、摘要、作者自评或模糊缩略图替代。未过门槛可能只是证据不足，不能直接给 1 分或用 3 分填空；只有封面、叠页宣传图或半张正文时标“待检查”，不虚构确定的整套视觉评分。

### 评分置信度

| 等级 | 证据要求 | 推荐限制 |
| --- | --- | --- |
| 高 | 来源所示页面完整、清晰，已检查的页数与声明范围一致，五维观察依据充分 | 可按用途门槛推荐，仍需用户复核；不代表源码或导出已验证 |
| 中 | 至少有一张完整清晰正文页，但已知续页未取得，或部分细节不能确认 | 可以限定为“已检查页面的参考”，列明缺失；不能声称整套或实用能力已验证 |
| 低 | 只有不完整页面、模糊缩略图、严重遮挡，或实际图片无法查看 | 标待检查，不计算完整综合分，不直接推荐，也不借“特别发现”绕过 |

置信度表示证据充分程度，不给质量分加减分。原图链接不可取得，但实际打开的完整清晰截图足以判断时，仍可据图评分并注明获取方式。只看过第一页、已知第二页未看，不能把整套标为高置信度；缺失的源码、中文试排和 PDF 验证分别记录，不凭高视觉置信度补齐。

## 4. 五个维度与权重

每项满分 5 分，权重合计 100%。每项分数必须有页面上能指出的观察依据，不能只写“高级、专业、好看”。

| 维度 | 权重 | 评什么 |
| --- | --- | --- |
| A. 清晰易读 | 30% | 正文辨识、对比、行长、行距、段距，以及整体阅读顺序 |
| B. 专业可信 | 30% | 标题、辅助信息与正文的对应关系、信息主次及格式一致性 |
| C. 内容替换与容量适配 | 10% | 能否用用户真实内容替换，正文段落容量、目标语言与续页空间；不评原栏目名称是否相同 |
| D. 视觉精致 | 25% | 字体比例、配色、留白节奏、线条及装饰细节的完成度 |
| E. 可复用重建性 | 5% | 布局和元素是否可辨认、可分层重建，替换内容后能否沿用规则 |

个性表达不设独立加分项，进入第 7 节的偏好选择；不要求模板“有个性”才能通过。清晰与专业各占 30%，视觉精致固定占 25%；bot 不得为让某张图通过而临时改权重。

### 先校准分档，再评分

| 分数 | 统一含义 |
| --- | --- |
| 5 | 示范级：该维度处理成熟，可作为高质量参照，具体细节经得起检查 |
| 4 | 优秀：在基础合格之外，有明确、可指出的设计优势，值得优先借鉴 |
| 3 | 普通合格：基本清楚、规整、可用，但该维度没有充分体现出优秀水准 |
| 2 | 存在明显弱点：有具体设计问题，需较大调整；不能仅因普通或常见就给 2 分 |
| 1 | 严重失效：该维度的基本任务无法完成 |

**3 分是正常档，4 分是优秀档。** “没发现明显错误”“对齐整齐”“颜色统一”“能换文字”只能说明相应基础要求得到满足，不能单独成为 4 分依据。打 4／5 分时，须指出比本维度 3 分锚点多做好的具体处理；没有依据就保留在能支持的档位，不把未知填成 3 分。

评分不设高低分配额。简单、常见或黑白版式也能因优秀的字体、比例、留白和信息组织得高分；新颖、复杂、装饰多也不能自动加分。某张作品整体普通，不意味着所有维度都差，保留其真实强项，不为贴合预期总分统一压分。

同一缺陷主要归入一个维度，避免重复扣分。例如字体过淡归 A，条目与辅助信息归属混乱归 B，碎片指标难以替换为真实经历归 C，装饰比例失衡归 D。确有不同影响时，分别说明具体影响。

### 每档分数的标准

#### A. 清晰易读

| 分数 | 可观察标准 |
| --- | --- |
| 5 | 密集或长短混合内容仍有稳定阅读节奏；关键经历、辅助信息与细节能快速定位，连续阅读和跨模块浏览都顺畅 |
| 4 | 字级、行长、行段距与分组配合得当，重点容易扫到，正文读起来舒展；能指出具体区域如何帮助阅读，而不只是文字能认清 |
| 3 | 正文可辨、顺序能跟随，分区基本清楚；字号、密度和段距处理常规，阅读体验合格 |
| 2 | 多个区域文字偏小、偏淡、挤压或阅读路径反复，明显增加辨认负担，需要较大调整 |
| 1 | 设计导致正文大面积无法辨认、重叠，或无法确定主要阅读路径 |

先排除图片压缩、模糊等证据问题，再评价设计。不从截图猜精确字号；分辨率不足时标待核实，不把图像质量误判为模板可读性。

#### B. 专业可信

此项只评呈现方式，不认证示例内容的真实性或招聘效果。原模板没有公司、项目、日期或自我评价时，不按缺项扣分；看其已有信息是否对应清楚，相关求职字段能否自然补入。

| 分数 | 可观察标准 |
| --- | --- |
| 5 | 信息主次、条目归属与辅助标注形成成熟的组织方式；长短不同、层次较多的内容仍一致，招聘方易于判断经历关系 |
| 4 | 同类格式稳定，角色、组织、时间等已有信息主次明确；标题与辅助标注克制，版面重点集中在候选人的经历，能指出优于基础分组的组织处理 |
| 3 | 分组、标题及条目归属清楚，格式基本一致，可以正式求职；信息主次和标注方式较常规 |
| 2 | 多处条目归属、标题层级或格式不一致，需要推断信息关系或重新组织 |
| 1 | 无法识别标题与正文的基本归属，结构难以形成清楚的经历记录 |

有公司、角色、日期等信息时检查其归属，不存在时不虚构缺陷。单栏与双栏都可以专业，不因颜色多就判“不可信”。技能百分比、雷达图不能代替真实能力说明；难替换的零碎指标按 C 评价。

#### C. 内容替换与容量适配

评估换入用户真实材料所需的结构改动，不比较原文与用户的岗位、主题或栏目是否一致。改栏目名、换示例文字、合理拆分或合并大模块不单独扣分；不要求参考模板有项目实践、个人评价等全部栏目。

| 分数 | 可观察标准 |
| --- | --- |
| 5 | 对长标题、多段经历、不同内容密度及需要的续页有成熟安排；保留主要版式即可承载丰富内容，不依赖删减关键事实或缩小正文 |
| 4 | 可见结构对丰富工作／项目描述有明确容量和伸缩空间，能调整模块篇幅且不破坏主布局；指出具体空间或组织依据 |
| 3 | 基本可以改标题、换文字，能放常规段落；现有示例支持一般容量，尚未体现对更丰富内容的优秀适配 |
| 2 | 主体多为短标签、独立指标或固定图表，正文容量明显受限，换入经历需大幅改列宽、卡片或结构 |
| 1 | 几乎没有可用于真实经历的文字空间，无法承担正文母版 |

英文或单页模板不自动扣分；依据可见栏宽、内容长度和续页规则预估目标语言与页数适配，未实际试排标明“据图预估”。没有展示续页不自动扣分，也不能凭空宣称续页规则成熟。

重点检查“连续超过 5 条”的零碎无关指标。数量是检查信号，不是机械否决线：这些指标难以合并或替换成真实内容、需要硬凑信息或大幅重排时，C 最高 2 分，不进入实用模板候选；视觉用途另按第 5 节判断，不能绕过用户明确排除的结构或风格。即使不足 6 条，主体明显难用也可据实低分。

| 参考情况 | 判法 |
| --- | --- |
| 其他行业简历没有项目或自评，几个大栏目叫 A／B／C／D，但有清楚的段落和标题空间 | 可以进入评分，改名和换内容不扣分 |
| 连续 8 项体脂、体重、BMI、血糖等数值卡片，正文空间少，也难换成真实经历 | 因结构难替换而不进实用候选；用户已明确排除的无关指标结构不能换标签绕过 |
| 有 6 个以上条目，但可直接填入真实技能、经历或成果，版面仍能容纳正文 | 不因数量淘汰，按实际替换成本与容量评分 |

真实项目截图、作品或成果图表有明确用途时可保留；主题无关但版式可替换的图文块也可借鉴。不要为保留模板虚构指标、凑标签或删掉关键经历。

#### D. 视觉精致

| 分数 | 可观察标准 |
| --- | --- |
| 5 | 字体比例、版心、留白、色彩与细节有成熟且统一的设计语言；整体和局部都经得起检查，值得作为完整视觉主参考 |
| 4 | 字体搭配、比例、间距节奏、配色或细节至少有明确优秀处理，并与全页协调；能指出值得借鉴的具体设计，而不只是无错、整齐 |
| 3 | 整齐、配色基本协调、风格统一，但字体、留白和装饰处理常规，作为视觉参考的优势有限 |
| 2 | 字体比例、装饰占比、留白节奏或配色存在明显失衡，多处细节粗糙，需较大调整 |
| 1 | 字体、颜色和装饰杂乱，难以提取稳定的视觉样式 |

朴素与精致并不冲突。黑白、单栏、少装饰都可得 4／5 分，但须有优秀执行的证据；仅因“干净简洁”不直接给 4 分。渐变、头像或立体效果本身不加分，也不因没有它们扣分。常见版式不自动低分，罕见版式不自动高分。

#### E. 可复用重建性

| 分数 | 可观察标准 |
| --- | --- |
| 5 | 网格、字级、间距和分层规则成熟且可解释，能支持不同内容长度与必要续页，替换后仍易保持一致 |
| 4 | 可从多个区域提取稳定的栏宽、字级、间距和元素关系，重建与替换有明确规则，不只是一张图容易临摹 |
| 3 | 元素与分层容易辨认，能重建常规版式；未体现更完整的布局规则或内容变化处理 |
| 2 | 多处尺寸、分层或元素关系难辨，高度依赖固定内容，替换经历需要大量试排和替代设计 |
| 1 | 只能保留整页图片，无法形成可更换正文的母版 |

没有源文件不直接扣视觉评分，有源文件也不自动加分；截图不能证明原文可编辑。纹理可作为独立图片层，不要求所有效果都用矢量。此项为据图预估，不承诺已在目标工具中验证。同等质量的实用候选，优先核查合法可得的可编辑源文件、中文排版与 PDF 导出，实际状态按第 5 节另记。

### 半分与未知信息

各维度默认用整数档。确有证据表明介于相邻档时，允许半分并说明差距；不强制每项带小数，不给无锚点的 4.3、4.4 或 4.7 分。比起细分零点几，更要说明为什么达到 4 分、仍有哪些缺陷。

没有证据就标“待核实”，不要用 3 分代替未知。C、E 可以依据可见结构给预估分，注明“未试排／未重建”；不因尚未制作就一律无法评估，也不凭被裁掉的内容补分。

## 5. 加权计算、用途与推荐门槛

各维度得分乘权重后相加，满分为 5 分，不按维度数量求平均。

```text
S = A × 30% + B × 30% + C × 10% + D × 25% + E × 5%
  = A × 0.30 + B × 0.30 + C × 0.10 + D × 0.25 + E × 0.05
```

保留未舍入乘积求和，显示两位小数仅用于复核算术；准入使用未舍入的 S，不把 4.30 与 4.40 宣称为可重复验证的审美差异。存在待核实维度时不计算完整综合分，不重新分配权重。

### 独立评分与反向验证

- 先依据实际图片的字体、对齐、留白、层级、网格及内容承载结构评分。尽可能不给评分阶段传热度、点赞、作者、平台名、宣传标题或地区配额；这些信息只用于追溯与结果组织，不能成为加分或扣分理由。无法完全隔离时如实说明，不冒称盲评。
- 单张作品的原分先确定，再按地区、用途、多样性与偏好组名单。不能为了凑国内或海外比例调整分数。
- 对所有 S ≥ 4.0 的作品做反向检查：指出真实可见的不足、对应影响，并说明为何未到更高档。不能把“还没拿到源码”“没看续页”等验证限制冒充已观察到的视觉缺陷。
- 复查后确实没有发现明确不足，写“在已检查范围内未发现明确不足”，说明已核对哪些锚点并交人工复核；不编缺点、不自动扣分，也不因缺少批评强行升分。5 分已是满分，说明符合锚点即可，不虚构更高一档。
- 反向验证不能推翻已确认的事实或强迫每种风格都符合某个审美标签。评分理由、真实不足与核实限制分开记录。

### 两种用途

所有正式推荐都须：实际看图并通过第 3 节门槛、五维有依据、S ≥ 4.0、A、B、D 各 ≥ 4.0、置信度为高或中，且不触犯用户明确偏好。中置信度须限定已检查范围。

| 用途库 | 额外门槛 | 能说明什么 |
| --- | --- | --- |
| 视觉灵感库 | C、E 保留真实低分，不要求达到实用下限 | 可研究字体、留白、层级、网格或复杂视觉风格；不能自动投入求职使用 |
| 实用模板候选库 | C、E 各 ≥ 3.5，能合理承载真实工作／项目内容 | 具备进一步使用或重建的条件；仍需检查源码、中文与 PDF |

D 的下限适用于两种用途：视觉仅属普通的模板，即使其他项把总分补到 4.0，也不进入本轮高质量参考名单。可以如实记录其日常可用价值，不把“未推荐”写成“不能求职使用”。

两个库是同一作品的用途标签，不重复下载或计数。作品可以同时进入两个库；正式推荐总数按唯一 ID 控制为 10—20 个。视觉优秀但结构复杂的作品可以只进入视觉库，不抬高 C／E 分来凑实用资格。没有源码仍可成为视觉参考，甚至据可见结构进入“需重建”的实用候选，不能直接认定已可使用。

实用状态分别记录：源文件未提供／已取得未打开／已在目标工具核验；中文未试排／已试排；PDF 未导出／已导出未检查／已检查。优先核查有合法可得源码的候选，但宣传页写“可编辑”不算验证。只有相关能力实际检查通过，才标“已验证可用”。

S ≥ 4.5 且满足相应用途条件，可列为该用途的质量优先候选；4.0 ≤ S < 4.5 为合格候选。分数接近时综合证据、置信度、设计多样性、偏好与使用目标，不靠百分之一的分差机械排序。

以下只演示计算，不代表真实图片评测：

| A（30%） | B（30%） | C（10%） | D（25%） | E（5%） | 显示分 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 4.5 | 4 | 4 | 3.5 | 4 | 4.03 | S=4.025；D 未过共同下限，两种用途都不正式推荐 |
| 3.5 | 5 | 5 | 5 | 5 | 4.55 | A 未过共同下限，不进入正式推荐 |
| 5 | 5 | 3 | 5 | 5 | 4.80 | 可作视觉参考，不能作为实用候选；仍须证据与偏好过关 |
| 4.5 | 4.5 | 4.5 | 4.5 | 4.5 | 4.50 | 两种用途都达线，仍待人工复核 |
| 3 | 3 | 3 | 3 | 3 | 3.00 | 普通合格，不正式推荐；有代表性的高估误判可留作校准 |

3 分作品不是无用作品，不要求将普通合格者都收入 Bad Case。Bad Case 也可表示 Bot 将普通作品误荐为优秀，须写清误判类型。

例如第一行：4.5 × 30% + 4 × 30% + 4 × 10% + 3.5 × 25% + 4 × 5% = 4.025，显示 4.03。质量通过、个人喜欢、实际可用是不同结论。

## 6. 执行流程与特别发现

1. 检索模式先读取案例库说明及 Good／Bad Case 索引，用已有人工确认案例校准，尤其检查真实误判的理由；未复核例只当 Bot 历史判断，不能当人工真值。无需把建库或补齐案例作为搜索前提。
2. 按第 2 节当前阶段的规模跨行业检索、记录来源，去重并分配唯一 ID；原栏目不必与用户一致。真正打开完整图片后才评分、标置信度及用途，访问失败或模糊的标待检查。
3. 完成计划评测后，选取 10—20 个正式候选。尽量覆盖单栏、双栏、编辑式、网格式、不同字体与层级组织，避免全是同一版式的换色；不为每种风格硬定数量，也不为多样性降质量。
4. 正式候选按国内／其他地区和用途整理，地区不明单列。聊天每批最多展示 3 套，完整结果在索引查看，不要求逐批确认才能拿到总包。地区 60:40 针对正式唯一作品，不包含 Bad Case 或特别发现。
5. 所有实际评过的不合格作品保留来源、图片路径或实际看过的图片链接、原五维分、理由与状态；不因不推荐而删除记录。精选约 5 个明显差、有代表性缺陷或被高估的 Bad Case 保存图片，供后续人工复核。
6. 可额外选最多 2 个“特别发现”：说明独特的时间轴、项目组织或字体等局部价值，以及为何未进正式名单。它们不计正式推荐数、不算 4 分以上合格作品，默认不标 Good Case；仍须真实看清图片、来源可追溯，低置信度或无法查看的图不能借此推荐。
7. 按第 2 节停止条件汇总实际数量、缺口、耗时和发现率。已有候选数量不能冒充搜索或评测量；重跑要保留旧记录，区分复用与新发现，避免重复计数。

本流程实际搜索时保存记录和参考案例；只维护规则或案例库目录时不自动搜图、下载新候选或编造样本。用户已提供并授权留作校准的图片可据实收录。购买、上传和重建设计遵守用户实际授权，低分不等于可以删除用户文件。

## 7. 高分但用户不喜欢

每批只需用户选择“喜欢／局部喜欢／不喜欢／都不喜欢”，也可选最接近的一张；不要求用户再评五个分数，说不清原因也有效。

| 反馈 | 下一步 |
| --- | --- |
| 喜欢整套 | 作为本次简历的偏好参照，不推断每个细节都喜欢 |
| 局部喜欢 | 记录明确喜欢的配色、字体、布局或质感，不把整套标成认可 |
| 不喜欢，给了原因 | 排除该模板，按明确原因调整后续搜索；例如明确不接受黑底，就避开黑底正文 |
| 不喜欢，说不清原因 | 排除该模板，下批换有区别的高质量方向，不臆测用户讨厌整个风格 |
| 都不喜欢 | 换方向，必要时请用户给更接近的参考；不争辩“都超过 4.5 分”，不重复堆同类图 |

只记录明确反馈、对应模板或特征及适用范围；默认用于本次求职简历，不上升为用户所有设计任务的永久偏好。偏好未知就如实标注，用户改变想法时以最新反馈为准。

保留原有质量分及依据，不因用户不喜欢就事后改低，也不因喜欢就改高。用户指出“评分被高估”等质量问题时，检查证据和分档；必要时另记新规则下的重评，保留原分，不把质量纠偏误当作单纯审美偏好。明确拒绝具有否决效力；最终采用由用户决定。

最终由用户人工复核，再确认 Good Case／Bad Case。Bot 初筛归类为“待人工复核”，人工分和反馈没有就留空；不将自动标签作为 Benchmark 真值。区分质量问题、个人偏好与实际可用性，保留 Bot 当时的预测、理由及规则版本，人工反馈另记；重评不能静默覆盖原判断。

公开模板的参考图与设计评测保存在本 Skill 的案例库，供模板复用和 Bot 检索校准；用户本人简历、联系方式、私人履历及投递材料留在求职项目，不复制进全局案例库。案例结构与记录字段见案例库说明。

## 8. 结果与评测记录的交付

正式推荐按国内／其他地区分组，并区分“视觉灵感／实用候选”标签；双标签不重复计数。集中在 Good Case 索引里展示 10—20 个高质量作品，每套提供：

- 唯一 ID、名称、来源及语言，主要市场与依据；转载如实注明。完整实际预览、已获取页数、是否缺续页、图像获取方式和本地保存状态，不能把链接称作已交付图片。
- 五维分数、固定权重、各项具体观察、加权计算及综合分；保留缺陷，不只写好看。维度以整数档为主，半分有依据。
- 对 4 分及以上作品记录反向检查的真实不足、影响与未得更高分的依据；未发现明确不足时如实记录复查范围，不编造。
- 高／中／低置信度及理由、已检查范围、未核实事项。低置信度不进正式推荐。
- 用途与实用验证状态、偏好待确认或对应的明确依据；不把“用户未反馈”写成“用户喜欢”。
- 值得借鉴的 1—2 点、换入用户内容时的主要调整；初筛不逐套制作风格报告或母版。

Bad Case 约 5 个单列索引，保存真实预览、来源、Bot 原分与理由、人工分及反馈；未复核留空，后台可查，不与正式高分名单混放。其他已评失败案例也保留简短评测记录，不必全部下载成图库。

“特别发现”最多 2 个另列，明确标“非正式推荐”，注明局部价值与未通过原因。只有实际来源图片可以作为参考，不生成或伪造。

本轮记录另存搜索发现量、去重量、完成评测量、待检查量、正式名单／Bad Case／特别发现的 ID、地区比例、耗时、可核实费用及发现率。数据不足就报告不足，不能靠空记录或重复图满足实验目标。

## 9. 图片交付、风格拆解与目录

### 图片交付

- PNG／JPG／JPEG 是主要预览格式；“原图／截图”是获取方式，分开记录。优先取得清晰原图，保留实际文件格式，不把 JPG 改扩展名冒充 PNG，也不放大或生成不存在的细节。
- 无法取得原图时，保存完整正文页的 PNG 截图，避免网页菜单或浏览器边框占主体；标明“正文页截图”。原文件是 WebP 等格式时可保留原件，需要统一预览则另取真实 PNG 截图；只有 PDF 时可保留 PDF，并渲染实际页面为 PNG 预览。
- 每张预览以一页完整正文为主，不用拼贴小缩略图代替。建议单页宽约 1200 像素以上，以实际能读清文字为准，不机械按像素淘汰，也不对模糊图插值放大凑尺寸。
- 多页按“正文-01.png”“正文-02.jpg”等实际格式分别保存，同一套只计一次。只取得一页就记“已获取 1 页”，不能把未取得的第二页或宣传图中的纸张当作已交付。
- 不强制收集 .fig、字体包或其他设计源文件。有已授权且实际可得的源文件可一起保留，但截图和原图都不能冒称可编辑源稿。

### 什么时候提取风格

先搜集、评分并交付参考图，用户通过索引选主参考。初筛每套只记 1—2 个值得借鉴的点，不逐套写长篇分析。

用户选定主参考后，再提取制作所需的版心、分栏、文字层级、字体气质、配色、间距及装饰做法。以参考版式为基准换入用户真实内容，先试排一页，再调整模块与密度；不复制他人履历，不把整页图覆盖文字称为可编辑简历。只有用户要求重建设计时才做这一步，不将风格拆解作为找图交付的前提。

### 全局案例库与项目路径

- `case_root` 默认指本 Skill 的 `assets/template-library/`，存公开模板参考、Good／Bad Case 及人工设计反馈。入口为“模板库说明.md”，分别链接 `good-cases/案例索引.md` 与 `bad-cases/案例索引.md`。
- `template_root` 指当前求职项目的工作目录，存本轮检索与失败记录、特别发现、用户实际简历及选中的可编辑母版。项目文件可用案例 ID 引用全局图片，不重复复制同一模板。
- 全局案例库 Good Case 索引通过“视觉灵感／实用候选”标签形成两种用途视图，同一 ID 和图片只存一次。约 5 个 Bad Case 单独保存；其余失败评分记录留在本轮项目记录中。
- 同机其他 Agent：交接两个根目录的绝对路径和案例库入口。结构化资源路径相对其明确所属根目录；Markdown 图片或文件链接相对于该 Markdown 文件所在目录，读取时以该文件的绝对父目录解析，不能相对 Agent 的工作目录猜路径。
- 跨机器：转交实际案例目录或压缩包，接收方重设 `case_root` 与项目根目录。给出 Mac 路径本身不能让远端访问；不擅自上传、创建共享链接或假设读写权限。
- 个人本机路径只写项目执行配置；全局 Skill 使用上述相对结构。根目录无权限或文件未取得时如实说明，不另建同名目录假装已找到原件。
- 本轮允许建立含说明与索引的 Good／Bad 目录；尚未搜图时索引明确记“0 个实际案例、未运行实验”。每个具体模板的图片目录仅在真实取得图片时创建，不填假图、假分或空案例。

## 10. 固定评测集与规则版本验证

本流程从 v1.0.0 开始受控记录；此前未编号历史不补造版本。每次修改评分 Prompt、维度定义、权重、门槛或判断指令，都更新版本号，保存修改前后规则／Prompt 快照，并在 `references/template-evaluation-versions.md` 记录原因、影响范围、保留规则及测试结果。

已有固定人工评测集时，每次上述修改后都必须用同一批图片重评并比较，未运行不得标为验证通过。固定集位于 `case_root/benchmark/评测集清单.md`，只纳入用户已经确认评分或通过结论的 Good Case、Bad Case、边界案例；边界是样本标签，不再复制一套图库。清单绑定实际图片、已检查页、图片校验值、人工评分／用途结论、固定集版本与人工标注版本。样本或标签变化要新建相应版本，不能看完新版结果再偷偷换测试题或人工答案。

版本测试与检索校准分开：评分者只接收中性 ID、固定图片和待测规则，隐藏 Good／Bad 目录名、人工答案、旧分与旧理由；先固定新评分，再由对照步骤读取人工答案比较。必要时用中性名称的固定图片快照，不能让路径名泄漏标签；图内无法隐藏的作者信息如实记为限制。

同一规则含义下，对同一批样本比较：

- 评分平均偏差：平均（Bot 分 − 人工分），用于观察整体高估／低估；同时报告平均绝对误差，避免正负抵消。
- 误通过率：人工明确不通过却被 Bot 判为正式通过的数量 ÷ 人工明确不通过的数量。按视觉／实用用途分别核对，个人不喜欢不能自动当作质量不通过。
- 同时报告样本数、误通过个数、缺失结果和无法评分项。分母为 0 或没有人工分时写不可计算，不填 0% 或 0 分误差；新版缺失结果不得静默删出对比。

人工只给区间时保留区间与原话，不擅自取中点或反推分项；只有明确的质量不通过结论才计入误通过指标。缺少人工精确分时不计算精确均值误差。参与制定本轮规则的案例属于样本内开发检查；隔离评分输入也不能将它称为独立泛化验证，后续需用未参与修订的新案例检查。

若只改权重且人工分项与维度含义完整一致，可按新权重重算并记录派生标注版本；没有分项、维度含义或通过定义变化时，保留原答案，请用户确认新标注后再作相应数值比较。仍使用相同图片，不能把不兼容的旧综合分直接当新标准真值。

新版平均分变高不代表效果更好。结合误差、误通过率、具体误判与人工复核决定保留、回退或继续验证，不只看 Bot 自评分。当前固定集没有人工样本时，只登记“未建立／无法进行图片回归”，可做结构和规则场景检查，但不得声称评分效果已验证、指标改善或已获准扩围。
