# Agent Blueprint

> 整合版：由 [产品开发总入口](../../SKILL.md) 调度；统一项目目录、当前 PRD、阶段与授权以 [流程契约](../../references/workflow-contract.md) 为准。默认由当前会话按手册分析，不另配模型接口。

复用本地 Agent Blueprint 的方法、组件说明和程序，支持跨项目规划与检查。按当前任务取用必要部分，保持用户已确认的需求、范围和实施授权。

## 定位引擎与目标项目

- 本 Skill 与完整引擎位于本文件所在的模块目录，按实际路径定位，不依赖原作者机器。
- 解析本 `SKILL.md` 的实际路径，以其所在目录为引擎根目录，并确认该目录同时包含 `使用引导.md`、`BLUEPRINT.md`、`blueprint/`；无法定位时说明缺失路径。
- 引擎是共享工具，目标项目是用户本次要规划或检查的项目。反向检查必须核对目标路径，避免把引擎自己的示例算进目标项目。
- 先读引擎的 `使用引导.md`，再按任务读取 `BLUEPRINT.md` 的相关章节及所需 `s01` 至 `s17` 组件说明。需要核对程序行为时再读 `blueprint/cli.py`、`rules.py` 或 `scanner.py`。

## 选择工作方式

默认由当前会话按手册分析，无需另配模型接口。报告注明“当前 AI 按手册分析，未运行模型管线”。可复用现有离线扫描和选型函数，但必须区分规则扫描与人工判断。

仅在用户已授权本次额外模型 API 调用及其费用时运行真实模型管线；已有密钥不等于费用授权。不自动执行安装脚本或修改共享配置。模型调用的次数和 token 限制不等于金额上限，预算触发后停止并说明原因。

需要运行可选程序时，先检查已有 Python 解释器与实际依赖。公开包不含 `.venv`，不能假定 `.venv/bin/python` 存在；环境缺失时跳过可选 CLI，继续由当前会话按手册分析，不自动安装。只有取得相应安装授权后才补环境。环境已有时在引擎根目录用已确认的解释器运行 `-m blueprint`，先查看对应子命令的 `--help`，显式指定目标输入与绝对输出路径。`--mock` 只验证程序流程，不能作为真实项目分析结果；`--resume` 仅用于继续同一个任务。

## 按任务交付

### 想法或 PRD 到方案

按蓝图完成需求拆解、五要素建模、必要组件选型和架构设计。缺失事实标“待确认”，只追问会影响下一步的关键选择。

方案按需求包含目标用户与业务闭环、工具/知识/观察/行动/权限、组件选型理由、架构图、工具输入输出与副作用、权限和失败处理、成功指标及部署考虑。需要完整架构时采用蓝图的七层结构；只问某个组件时直接回答该组件。

### 已有项目到差距报告

优先对照用户提供的 PRD 和当前已确认需求，结合实际源码检查。每个主要缺口附文件位置、行为证据或证据不足的说明，给出影响与改进优先级。

区分“未扫描到”“静态源码表明缺失”“运行验证失败”；示例代码、扫描分数、测试替身通过均不代表真实集成或生产验收。反推的 PRD 标为待用户核对的草稿。

### 后续实施

用户只要求方案或检查时，交付到该范围为止。用户已明确要求实施或修复时，沿用现有授权继续推进，不因本 Skill 再次要求确认同一方案；遵守目标项目规则并完成相应验证。

## 输出位置与复核

- 产出沿用目标项目现有目录结构；没有约定时，在目标项目内新建 `docs/agent-blueprint/任务名/` 保存交付物。项目尚未建立时，先确定其位置再写文件。
- 手册中的引擎 `out/` 是程序默认值；跨项目使用时显式指定目标项目内的输出目录，不把不同项目的报告混进共享引擎。
- 新任务使用新文件或新子目录；不覆盖既有文件。变更既有文件按用户的确认规则执行。
- 交付前检查内容与输入一致，保留未知项、证据和验证限制。真实模型审稿、当前会话自查、模拟执行分别说明；只有实际验收通过才称“生产级”。
- 最后说明关键结论、待确认项、实际验证范围和交付物绝对路径。
