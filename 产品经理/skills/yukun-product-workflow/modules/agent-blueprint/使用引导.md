# 蓝图模块使用引导（产品开发整合版）

本模块只提供需求到架构的推导方法、离线选型工具、参考实现与可选模型管线。统一入口是 [yukun-product-workflow](../../SKILL.md)，项目位置和授权沿用 [流程契约](../../references/workflow-contract.md)。

## 先接上游材料

先读取目标项目已确认的立项底稿、当前 PRD 和项目状态，不重复询问用户、问题、范围和已定约束。输入至少包含目标、用户、核心闭环、交付物、边界和约束；只补会改变本轮方案的缺口。

## 输出到独立业务项目

业务项目必须在总 Skill 包外。默认产出放在目标项目的 `docs/agent-blueprint/`，代码写进该项目的既有源码目录；当前 PRD 只有 `docs/PRD/PRD.md` 一份。既有项目已有约定时沿用并在项目状态中索引。

不把业务代码或报告放进本模块的 `out/` 或 `skeleton/`。不使用旧产品循环的 `init`、`revise`、`verify` 命令管理统一工作区：它们仍保留为历史程序功能，但绑定另一套文件布局。新需求先更新当前项目的需求与状态，再增量修改，不重建项目。

## 默认当前会话分析

读 [BLUEPRINT.md](BLUEPRINT.md) 的需求拆解、五要素与必要组件章节；非 Agent 产品不强塞 Agent Loop、记忆或多智能体。完整 Agent 架构可采用七层图，不需要的层标 N/A。

默认注明“当前会话按蓝图方法分析，未运行额外模型管线”。无需安装依赖或配置另一把 Key。`setup.sh` 会安装依赖并创建本机配置，不能自动执行。

仅当用户另有明确的模型调用与费用授权时，才考虑程序 `plan` 或 `audit`；先查看相应 `--help`，显式传入当前 PRD、目标项目与位于目标项目内的绝对输出目录。`--mock` 仅验证程序流程；程序调用/token 限制不能代替金额上限。

## 交付与验证

方案包含需求追溯、数据流、必要模块、输入输出、数据及工具权限、失败兜底和验收映射。结构化 `plan.json` 仅在真实生成并有下游需要时保留，不伪造程序记录。静态扫描结果与模拟输出均不能证明实际功能、模型质量或生产可用。

历史教学资料见 [示例目录](docs/examples/README.md)，其中“真实运行”只指原模块历史记录，不是本整合版新完成的测试，也不是实际业务 MVP 的验收证明。
