# 报告视觉：选模板、排版规则与交付前检查

本文件约束 HTML 报告的视觉和检查。内容职责、字段和组件见 [report-contract.md](report-contract.md)。

## 选哪套模板

| | 青柠 `lime`（默认） | 网格 `grid` |
|---|---|---|
| 气质 | 深色侧栏、圆角卡片、蓝与青柠色重点；信息密 | 纸色底、黑字、一种红色；留白大，像杂志版式 |
| 适合 | 评审会、逐条核对需求、给研发和协作团队看 | 展示、汇报、作品集、给决策者讲一个完整故事 |
| 目录 | 左侧八章 | 左侧八章，当前章展开小节 |
| 章节开头 | 小标签 + 章节标题 + 可选结论句 | 大号红色编号 + 描边英文背景字 + 结论句作大标题 |

- 用户点名了风格或用途时直接选；没说时问一句，并用上表的「适合」一行帮用户选。用户说「都行」时用 `lime`。
- 网格模板更依赖结论句：给每章写 `headline`，给 `meta` 写 `tagline`。没写时退回固定章节标题，版面成立但叙事变弱。
- 不要在一份项目里混用两套模板的样式，也不要在生成后的 HTML 里手改样式。需要第三种风格时按本文最后一节先出预览。

## 排版规则

这些规则来自实际评审反馈，两套模板都已遵守；往报告里加内容时也照着检查。

**不留空洞**

- 同一行的卡片等高。最后一行不足时让卡片铺满一行，不为了「错落感」留空白。
- 关键数字一组 2–5 个。数值长短差很多时整组用同一字号（生成器已自动处理）。
- 截图缩略图统一比例，说明文字对齐；完整图点开看。
- 内容区铺满目录右侧的可用宽度（到 1440px 为止），不要让右边空出一大块。

**装饰要么完整，要么不出现**

- 背景大字、图标、引号等装饰在桌面宽度下完整可见，不出现被裁掉一半的大数字或符号；放不下的窄屏直接隐藏。
- 装饰尽量由内容生成，即「内容即图形」：12 位用户画 12 个小方块，1280 条记录画一片点阵，P0／P1／P2 用实心、红框、灰框表示。不要画与内容无关的形状。

**字号和层次少而清楚**

- 全篇最多五级字号：特大展示、章节标题、导语／小标题、正文、注释。小号字只用于标签和注释，不用来塞长段落。
- 不是所有内容都装进框里。卡片、色块和直接写在底色上的文字混合使用；网格模板每章最多一到两个色块。
- 详细表格和证据放进折叠附录，正文只放影响判断的部分。
- 图表里的字和正文接近一比一，不让宽图缩到看不清。宽表格在自己的容器里横向滚动。

**断行：大标题和版本矩阵**

- 网格模板的章节大标题（`headline`）在桌面宽度（约 1440px）一行大约放得下 21 个汉字。写到 22、23 个字时，最后一两个字会单独掉到下一行。要么控制在一行以内，要么写成两行都比较满的长句。
- 版本矩阵（`roadmap`）的总宽度跟着格子里最长的那一行走（`.rm-grid` 设了 `min-width: max-content`）。格子里的内容写成几行短句、用换行分开，每行不超过 12 个字左右；这样四个专题列能在桌面宽度一屏放下，不用横向滚动。

**优先级与排期的口径**

- P0 核心，立刻做；P1 重要，下个版本；P2 以后再加。报告里不另造口径。
- 版本节奏按版本或阶段排，阶段数由项目决定。不要写死「7 天」「4 周」或固定数量的节点，模板和示例也一样。

**交互只做有用的**

- 可以加小交互，但要回答一个真实问题，例如按优先级筛选需求、放大截图、目录跟随当前小节。
- 动效只用于进入画面和导航反馈，遵守系统「减少动态效果」；没有 JavaScript 时内容全部可读。

## 交付前截图检查

生成后实际打开 HTML，桌面宽度（约 1440px）和手机宽度（约 390px）各看一遍，逐项确认：

1. 页面没有横向滚动；只有宽表格在自己的区域里滚动。
2. 表头一行、编号完整，没有一字一行或竖排。
3. 没有空洞：卡片等高、最后一行铺满、关键数字字号一致、截图对齐。
4. 装饰完整：背景字、徽章、编号没有被裁掉一半。
5. 目录能跳到每章，当前章高亮；网格模板还要看小节展开。
6. 有优先级时，点 P0／P1／P2 能筛选，切回「全部」能恢复；有截图时能放大并用 Esc 关闭。
7. 打开系统「减少动态效果」或关闭 JavaScript 后，正文、数字和表格仍完整显示。
8. 控制台没有报错。
9. 大标题没有一两个字单独掉到下一行；版本矩阵在桌面宽度一屏看得全。

能用无头浏览器时截图核对；不能截图时说明只做了哪些检查，不说「已经能用了」。

## 需要新风格时

用户不满意现有两套、或想要别的气质时，不直接改模板：

1. 找两三个可参考的优秀案例，说明各自的特点。
2. 用同一份报告内容做两三个方向的预览（一屏即可），让用户挑。
3. 选定后再整理成新模板。新模板复用现有组件的类名和插槽，满足本文的排版规则和截图检查，并在生成器的模板列表里登记。

模板只放通用结构和样式，不放任何项目的名称、数据或截图。
