# 实施模块规则（整合版）

本目录是公共参考模块，不是业务项目。完整执行由 [产品开发总入口](../../SKILL.md) 和 [实施适配](../../references/execution-adapter.md) 调度；业务项目内既有的规则与用户当前授权优先。

- 沿用已确认的立项、当前 PRD、蓝图与 `docs/项目状态.md`；不重复八字段访谈，不再问同一项是否开始。
- 所有业务代码与文档写进用户指定的独立项目，不能写进模块、本 Skill 包或全局目录；已有项目保留技术栈和目录。
- 先实现最小核心切片，再做界面与联调；失败处理、必要持久化和数据权限按项目风险实现。
- 模型输出校验、超时与有限重试；密钥不进代码、前端、提交、截图或日志。没有真实验证时保持待验证。
- 测试和构建按实际技术栈选择；不要删除测试、吞报错或把 mock 当真实模型结果。
- `verify.sh` 在本副本中是只读预检适配器，显式传 `--project-root`；它不执行测试、模型或服务，也不能签发 MVP 验收。
- 默认验证结果在对话汇报，阶段结论简记项目状态；不强制创建证据目录、闸门文件、验证日志或过程报告。用户明确要的截图、最终交付物和必要设计资料可保留。
- 默认终点是本地可验证 MVP；只有用户要求上线时再读部署手册。安装、花钱、发消息、发布和高风险动作继续遵守用户授权，历史价格与云政策需核对当前官方资料。

三份手册在 `docs/手册/`，只按当前阶段读取。手册中的固定项目布局、历史技术栈、套餐和证据包要求在整合模式下均按上述规则适配，不自动照搬。
