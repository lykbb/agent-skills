# 阶段与交接契约

## 工作区、当前版本与规则优先级

- 业务根目录由用户当前指定，必须在本总 Skill 包之外；既有项目保留其目录与技术栈。
- 默认当前 PRD 是 `docs/PRD/PRD.md`，唯一状态索引是 `docs/项目状态.md`；已有项目用其他位置时在状态里指向它，不能再造互相矛盾的正本。
- 立项正式报告/底稿默认在 `docs/立项/`，蓝图默认在 `docs/agent-blueprint/`；必要源码和启动 README 放业务项目。
- 用户和目标项目规则优先，其次总入口与本契约，再次整合适配，最后原模块参考。旧手册的固定工作区、重复启动确认、强制日志/证据包、自动安装或默认上云不带入整合模式。
- 不把本次业务资料、私人记录、模型输出或项目代码回写通用模块。

## 阶段接续

| 当前阶段 | 输入 | 正式输出 | 接续条件 |
| --- | --- | --- | --- |
| 立项 | 用户想法、已有资料、事实/假设 | 八章立项报告、工作底稿 | 核心用户、问题、目标体验和本版范围有确认；未验证处显著标记 |
| PRD 适配 | 立项需求、已有 PRD、已定约束 | 可实施的当前 PRD | 输入输出、异常、权限与验收覆盖本版闭环 |
| 蓝图 | 当前 PRD、实际环境与代码 | 必要架构、接口、状态、权限和失败设计 | 可追溯至需求；没有多余组件；关键技术缺口已处理 |
| 实施 | PRD、蓝图、已定决策 | 业务代码、必要测试、可启动界面/接口 | 实际用户核心任务可运行；mock 与真实能力分清 |
| 验收 | 当前代码、样本、运行条件 | 最终 README、状态中的验证结论 | 实际运行及必要失败/恢复路径已查；受限项不冒充完成 |

已有材料满足某阶段条件时直接复用；只有单点需求时不强制补全所有报告。用户明确只要规划则停在规划；全流程授权延续至当前目标，但不扩成发布、付费或其他未授权外部动作。

## 交接内容放在哪里

交接直接使用正式文档与项目状态，不另建 handoff.json 或回执。交接至少说明：目标目录、当前目标与授权范围、用户/核心闭环、已确认范围与非目标、约束与费用边界、需求 ID 与依据、事实/假设/待验证身份、当前版本、实际验证范围、阻塞和下一步。

三类确认：业务方向与关键取舍需要确认；额外费用或越权动作按用户规则确认；已经确认的选择不重复问。未知值不是零，用户确认假设也不使它变成实测事实。
