# MVP 验收：验证了什么，就报告什么

立项报告、PRD、蓝图、代码骨架、静态文件检查和 mock 演示各有用途，都不能单独证明真实 MVP 已验收。

## 本版核心闭环

从当前 PRD 选一条真实任务，用允许使用的样本走完输入、处理、输出与用户后续操作。核对结果是否可用，来源和必要条件是否保留；人工确认、异常与失败恢复能否按约定工作。只对实际覆盖的场景下结论。

## 按项目需要运行

- 工程：与改动相称的测试、类型/语法/构建检查；真实启动命令和本机访问方式。
- AI：已获授权的真实模型最小冒烟、输出结构与场景质量；mock 仅验证工程链路。没有 Key/授权时明确待验。
- 数据与动作：需要持久化时实际验证重启/恢复；需要权限时检查后端隔离；外部副作用按授权验证或标待验。
- 界面：实际操作正常/加载/失败状态，检查窄屏、键盘和可读性；仅检查源码不能声称浏览器已验证。
- 可重复使用：README 有完整启动/配置/验证步骤，配置中不含秘密；状态能让下一次接着工作。

不要求每个项目都做登录、流式推送、多智能体或云部署。某项不适用时解释原因；关键项缺失时交付已完成部分和具体限制，不把“未做”改写为通过。

## 只读预检器

在技能根目录运行 `python3 scripts/check_project.py --help` 查看参数，再显式传入包外业务目录和 `planning` 或 `mvp`。它只检查文件存在和源码候选，不读 `.env`、不执行项目代码、不调用模型，也不判断需求语义。

预检结果始终包含 `runtime_validation=not_performed` 和 `mvp_accepted=false`。退出码 0 只代表静态齐全；退出码 1 是缺项，2 是目标或参数不合法。不能把 0 当成上面任何真实验证的通过证据。

预检器识别本包默认的 PRD 和状态路径。已有项目采用其他位置时，按其实际正本位置人工核对并在状态索引；不为通过预检而迁移文件或制造另一份正本。
