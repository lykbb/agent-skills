# 从蓝图实施到本地 MVP

本文件接收同一业务根目录、当前 PRD、蓝图与已确认范围，不重新启动独立 starter-kit 项目，不把代码放进 Skill 的 modules、out 或 skeleton。

## 项目准备

新项目按需要创建必要代码与文档；项目规则和状态可参考 [项目规则模板](../assets/project-AGENTS.md)、[项目状态模板](../assets/project-state.md)。这些模板不能覆盖已有规则或正本。不要批量建空文件夹。

先用已有工具读环境与项目约定；缺依赖时说明用途和影响，按用户授权安装，不自动运行模块 `setup.sh`。业务秘密只在本地配置和平台 Secret 中，日志不输出值。

## 实施顺序

1. 根据当前项目栈先完成一个最小的用户任务切片：输入 → 处理/模型或工具 → 可使用的输出；优先验证最不确定的一段。
2. 按真实需要补持久化、数据权限、超时、有限重试、输出校验和失败兜底。只做闭环所需模块，不为用完 s01–s17 扩大范围。
3. 需要界面时先用代表页验证信息、操作与错误反馈，再补本版其他界面；检查键盘、窄屏和减少动态效果。已有界面沿用用户确认的风格。
4. 按实际栈执行有意义的单元/集成检查、类型或构建，再实际启动服务、操作核心流程。已通过且未受影响的检查不反复跑。
5. 结果写入当前 README 与状态，按 [MVP 验收](mvp-acceptance.md) 准确区分可运行、mock、实测、效果待验证。

按需读取 [通用技术手册](../modules/ai-product-starter-kit/docs/手册/AI产品Vibe Coding通用技术栈手册.md) 或 [前端手册](../modules/ai-product-starter-kit/docs/手册/AI产品Vibe Coding通用前端技术栈手册.md)。固定 FastAPI/前端组合只是历史参考，不强制替换现有技术栈。

## 验证记录与部署

默认在对话汇报检查与结果，在唯一状态文件简记范围和剩余问题。不强制另建日志、阶段回执、证据包或命令输出文件；实际要交付的截图/成片/数据与用户指定记录按项目需要保留。

预检器不执行项目代码。真实测试必须明确配置离线模式，不能仅清空一把变量就假定不会调用其他厂商。模型调用仍需本次费用授权；缺 Key 时工程可用 mock 推进，模型质量与真实端到端继续待验。

默认止于本地 MVP。只有用户要求上线时才读 [部署手册](../modules/ai-product-starter-kit/docs/手册/AI产品%20Vibe%20Coding%20通用上线部署手册.md)，核实当前官方操作、权限、预算和部署目标，再按授权执行。
