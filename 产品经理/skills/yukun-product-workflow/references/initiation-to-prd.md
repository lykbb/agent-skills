# 从立项报告接成可实施 PRD

先读已有底稿和当前需求，沿用需求 ID、优先级、依赖、角色与证据身份。八章报告回答“为什么、目标与取舍”，PRD 把本版范围落成行为契约，不能只复制功能标题。

每个入选需求补齐：

1. 谁在什么前置条件下触发，输入来自哪里，哪些字段必填。
2. 正常流程、输出与完成状态；AI 输出由谁使用/确认。
3. 空输入、失败、超时、证据不足、重试与取消如何处理。
4. 数据实体、保存与恢复；需要时写清访问权限和外部工具副作用。
5. 可执行的验收场景，以及失败时如何判断问题在检索、模型、工具还是界面。

保留“需求 ID → 立项依据 → PRD 行为 → 蓝图实现位置 → 验收”的对应关系，放进现有文档表格，不单独生成追溯报告。

已有 PRD 直接检查缺口，不重做访谈。只补影响当前开发的关键选择。用户获知并批准按假设做原型时，可以先实现相应切片，但在 PRD、状态和最终交付中保留限制，不能称真实业务效果已验证。

模板见 [新项目 PRD](../assets/prd-template.md)，已存在的真实资料优先。工程技术选型到蓝图/实施再细化，不用框架名替代用户行为。
