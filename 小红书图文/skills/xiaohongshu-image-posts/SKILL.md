# 小红书图文生成

## 按当前阶段推进

先判断用户要选题、框架、文案、图片还是局部改稿；已确认的内容直接沿用，不重复走完流程。用户提供的最新改稿或截图优先于旧稿；提取特点时区分作者补充的事实、表达偏好和一次性布局，不把截屏未显示的部分视为主动删除。

1. 选题：先给少量不同切口和推荐理由，不直接扩成完整文章。
2. 框架：明确一条主线、要解决的问题和必要内容；未定方向时不抢写逐页文案。
3. 文案：按当前要求交付可用文字。用户说“写段文案”时直接给短正文，不继续停留在分析。
4. 图片：按用户明确指定的单张或整组范围制作并检查；明确要求整组时完成该组，单纯认可当前图或讨论张数不代表授权生成整组。

默认按“框架 → 文案 → 文案确认 → 用户指定某张 → 生成并检查”推进；用户当次明确改变顺序时，以当次指令为准。用户说“第二张”“下一个”时，按已确定的顺序生成对应页，不重复确认题材和风格；顺序不明确时再问。用户要一张静态图时交付完整图片，不用交互组件替代。只要文案或框架时，不自动出图、创建网页或启动制作工程。

## 从材料里选题

- 优先读取用户最近笔记、相关课程记录和已有选题，再补公开来源。需要确认课堂原意时回到原始记录，清洗稿仅用于定位；疑似转写错误另行核验。未找到材料不能据此断言老师没讲过，外部补充和自己的推演不能写成课堂原意。
- 从实际问题、任务、使用卡点、决策取舍或有材料支持的观点切入，说明读者能理解什么、解决什么。保留经核实的关键分支和条件，避免仅换术语复述课堂内容；公开文案直接讲知识，不默认加入“老师说”。
- 选题或产品拆解时提供有区别的切口，不机械套五层框架。用户已选题时围绕该题推进，不另换案例、产品或主线。
- 用户要求“比较新”时，区分旧概念、近期论文、机制和产品更新；核实新在哪里及来源日期，不把仓库更新直接写成概念首创。
- 用户未实际体验的工具写成资料介绍或待体验选题，不写成亲测。热点和高互动方向只能作为候选，不能承诺“必爆”或未经验证的效果数字。

## 内容与素材真实性

- 技术内容优先用户已核实材料、官方文档和一手研究；版本、功能、价格等动态信息在使用时核验。把已验证事实、厂商说法、自己的推断和未知部分分清，不将方案写成实际运行结果。
- 原图、真实截图、风格参考与生成示意分清角色。真实界面不重新生成后声称原样截图；AI 生成的功能场景注明“设计场景示意”等必要状态。
- 截图保留有讲解价值的内容，遮挡需保护的信息。标题、来源标签和资料分享都必须有对应材料；不能为了真实感添加无依据的“内部规范”“面试真题”“官方认证”。
- 引用和核验说明按实际用途放置；可在聊天或正文交代的内容，不强行塞成图片上的小字或重复页脚。

## 默认视觉与封面

沿用用户认可的 Lovart、Skywork、Pi Agent 系列的干净、克制和清楚层级；这是默认审美，不是固定版式。

- 暖白或米白纸质背景，黑色主文字，少量品牌或主题色。细纸纹、轻微压印、纸片层次和柔和阴影用于增强质感，避免纹理太重、字面发糊或画面显脏。
- 封面先突出一个中文主题、具体问题或清楚的阅读收益，主标题在手机缩略图中可辨认。用字重、尺度、位置和图文关系建立吸引力，不靠堆满装饰。
- 对比题可用红绿等反差色表达真实差异，作为可选方案；保留暖白纸质和克制配色的默认方向。颜色应辅助信息分组，不制造没有材料支持的对立。
- 标题应有字形设计和力量感。用户指定优设等字体时先查已有字体；实际排版可加载字体，生图可使用真实字体样张作字形参考。不能把参考字形说成实际嵌入该字体，不能擅自安装字体。
- 图标按可见形状的视觉重心居中，统一可视尺度、上下留白和标签基线，不仅对齐外框。竖版流程按阅读顺序重新组织，不把宽横图硬缩成小字。
- 同组图片统一尺寸、边距、标题层级和必要标记。小红书静态图默认 3:4，参考尺寸 1086 × 1448；用户指定比例优先，跨平台不机械沿用。
- 避免大黑块、廉价霓虹、重复装饰和无用途的小字。只保留确实说明来源、步骤或示意状态的角标，不自动添加日期、页码、系列号和口号。

## 按内容选择表达

### 软件介绍

单软件介绍默认一软件一张：名称与核实过的官方 Logo、中文定位、简短介绍和一个完整使用场景。简介通常约四行、50–90 字，直接说明用途、用法和关键特色；下部场景可配少量辅助卡片。先查官网核对软件身份、定位和功能，纠正名称混淆；Logo 优先使用官方素材作参考，不凭印象编造。不能把未验证的能力、成绩或承诺放进示意图。

### 来源与工具推荐合集

封面突出主题与阅读收益，分类内容页承担名称、官网素材和具体用途。制作信息源、工具清单等合集，或从用户改稿中提炼此类文案特点时，读取 [推荐合集的分类、封面与文案](references/curated-recommendations.md)；不套用单软件一张的版式。

### 教程与知识图文

- 每页承担一个重点；根据内容选步骤、对比、循环、关系或案例，不套用软件海报的固定卡片数。
- 多概念封面用共同问题或中文主题统领，名称、角色和解释放进对应模块，不将多个英文名称堆成大标题；单概念介绍可用名称作主标题。
- 节点写清做什么、输入什么、输出什么；术语配落地解释，不堆抽象名词。操作教程用同一个问题贯穿效果、流程、关键配置和测试，主标题不挤占解释图的空间。
- 图示区分并列、顺序、条件分支、回路、资料供给和执行流。核心环节及可选环节不能混为一谈，新增节点要说明解决哪个问题。
- 用户要求 RAG 全流程时同时保留离线建库和在线问答，不擅自缩成某个客服案例。案例用于辅助讲解，不能改变已确认的内容范围。
- 未搭建或未测试的案例标明示意或教学性质；规则、权限、工具、重试上限及兜底按场景说明，不把框架支持写成自动完成。

### 个人观点与跨平台贴图

读取 [个人观点与封面设计补充](references/opinion-covers.md)。围绕用户真实观点、例子和疑虑组织内容，保持作者口吻；迁移平台时重新检查比例和裁切。

## 发布文案与互动

- 文案简短、具体、可扫读，按用户要求的篇幅交付。软件集合通常约 200–350 字，单软件更短；知识点和观点不强套“软件名｜用途”的结构。
- 开头尽快交代具体问题、场景或读者收益；正文分点解释关键内容，结尾按需要给一步能执行的建议，不强加哲理和金句。需要优化封面吸引力、正文排版或互动时，读取 [标题、开头与互动](references/hooks-and-interaction.md)。
- 用户已确认小红书发布文案可少量使用 emoji，这是仅限发布文案的例外：用于少量层次提示，不要求每段添加。笔记、技能说明、代码、注释和制作记录仍不加 emoji。
- 互动优先提出与正文有关、读者能具体回答的问题；真实且可分享的资料可自然提供，不默认用“扣 1 领取”或编造资料承诺。详细条件见互动参考。
- 不虚构亲测、效率提升、点赞率或评论率。少用“赋能”“颠覆”等空泛宣传，话题标签保留少量相关项。

## 生成、改稿与交付

用户明确要求当前图片后，先查看编辑目标或本组最近获认可图片，标明各输入的角色；沿用已认可的配色、纸纹、字形和边距，布局随当前内容调整。插画、纸艺封面和栅格图片改稿使用 imagegen 技能与内置生图工具；需要原样保留官网图片、字标或真实界面的推荐页，可将原始素材直接用于可控排版并导出 PNG。不得用生成重绘替代原图后声称原样保留；需要新纸纹或插画时，生图只负责这些生成部分。

局部文字改稿以最新获认可版本为目标，只改指定区域，保护其他文案、插图、位置、配色和画布尺寸；布局调整只改相关部分。改后对照输入图检查指定改动和其他区域是否漂移。用户说“太乱”时先重组信息层级和关系，不用更多装饰掩盖问题。

生成后检查文字、技术术语拼写、图示关系、素材真实性、手机缩略图可读性、图标对齐及实际像素比例。严格 3:4 要核对实际宽高，不能只依据提示词声称达标。

最终 PNG 保存到当前项目对应目录，沿用既有结构并创建新版本；保留未授权删除的旧版。默认交付图片或下载链接及实际尺寸，不自动创建提示词、制作说明和检查记录的 Markdown 旁文件；用户需要提示词、源码或记录时再交付。不要重复讲制作过程。

## 风格参考图

做同系列时查看当前使用者提供或已认可、且与当前题材最接近的参考图。公开包不包含原使用者的本机路径或私人图片；不能把文件名、旧截图描述或未附上的参考图当成已经查看的证据。

- 软件介绍可参考干净、克制的 Lovart、Skywork、Pi Agent 系列视觉方向；只提取层级与纸质表达，不把旧品牌、文案和案例串入新图。
- 知识教程可参考纸艺构图和清楚的标题字形；人物、术语、流程关系按本次实际材料重做。
- 未提供相应参考图时，依据本 Skill 的视觉规则制作并说明未核对原图；不要声称已经查看特定参考图片。
