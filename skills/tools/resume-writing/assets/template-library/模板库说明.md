- [固定评测集清单](benchmark/评测集清单.md)：保存已人工确认的 Good、Bad 和边界案例，供规则版本对比；当前 1 例，人工总分区间为 2—3，未提供精确分或分项。

## Good Case 的两种用途

“视觉灵感”和“实用模板候选”是用途标签，可以同时存在，不是重复保存的两个物理库。每个作品只有一个 ID 和一份实际图片；正式推荐以唯一 ID 计算 10—20 个及国内／其他地区 60:40。

视觉优秀不等于能够投入使用。实用候选优先核查可编辑源文件、中文试排与 PDF 导出，并保留未验证状态；没有源文件的图仍可作为视觉参考，不能叫作已完成母版。

## 记录方式

每个案例的详细记录集中在所属索引，不为同一例重复写多份评分文件。索引至少保留：

| 字段 | 要求 |
| --- | --- |
| 身份与来源 | 唯一 ID、名称、来源链接、主要来源平台、设计族、首次轮次、重复对应 ID 及依据、地区及依据、语言、评测日期／规则版本 |
| 图片证据 | 实际图片链接或路径、原图／截图／PDF 渲染、已获取页数、缺失范围；长期 Benchmark 优先保存实际图片 |
| Bot 初评 | 五维原分、综合分、观察理由、反向检查结果、置信度与范围、用途、未通过原因 |
| 实用状态 | 源文件未提供／已取得未核验／已核验；中文试排和 PDF 导出分别记状态 |
| 人工复核 | 人工分、Good／Bad／局部喜欢等结论与原因；未反馈就留空并标待复核 |
| 后续重评 | 必要时追加新的日期、分数与理由，保留原初评，不静默覆盖 |

Bot 初评合格或低分，都只是待人工复核的分类。只有用户实际确认的案例才能作为相应人工 Benchmark 真值。用户“不喜欢”与质量低分分开；源文件状态也不由审美评价推断。

## 选例与保留

- 当前检索方案为首轮初筛约 100 套不同作品，单个平台每轮最多 10 套；尽量分散来源，不要求遍历全部平台或等额取样。后续轮次先读历史评测和设计族，跳过旧作品及近乎相同的变体，具体计数与例外见模板搜索规则第 2 节。2026-10-17 首轮按此方案执行，入池 96 套新增作品，另做国内补充批 10 套。
- 首轮 Good Case 对应正式推荐的 10—20 个高质量作品；未人工确认时标“Bot 初评合格／待人工复核”，不冒称用户认可。
- Bad Case 首轮约 5 个，优先明显差、缺陷有区别或被高估的例子；后续真实的“Bot 4.5、人工 2.5”等误判尤其值得保留。不能只用模型旧评分自证新评分准确。
- 本轮所有实际评过的失败记录保留在求职项目的检索记录中；不必把几十张淘汰图都塞入此库。约 5 个精选 Bad Case 应保存实际看过的图片和来源；无法取得图片时如实注明，不能当作稳定图片基准。
- 最多 2 个特别发现单列在本轮项目记录中，不自动进 Good Case，不占正式推荐名额；用户复核后再决定是否纳入。
- 不删除旧样本或改低原分来掩盖误判。跨轮排重还须读取项目中全部失败与待复核记录，不能仅靠本库的精选例断言全历史无重复。重复检索用既有 ID，并保留来源、设计族及重复关系；若人工改变归类，先更新状态，涉及文件移动／删除仍遵守用户授权。

## 固定集与版本测试

边界案例是附加标记，可属于 Good 或 Bad，不复制一套图片。只有人工确认的评分或通过结论进入固定集；冻结图片与答案版本，修改 Prompt 或标准后用同集重评。评分者先不看旧分、人工标签或类别目录，对照步骤在新评分固定后才读取答案。检索校准不等于盲测，具体流程见固定评测集清单。
