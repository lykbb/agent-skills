## 黄金结构

### 顺序（重要程度从高到低）

**应届生 / 0-3 年经验：**
1. 基本信息
2. 教育背景（放前面）
3. 实习 / 工作经历
4. 项目经历
5. 技能

**3 年以上经验：**
1. 基本信息
2. 职业概述（可选，2-3 行）
3. 工作经历
4. 项目经历（挑重点）
5. 教育背景
6. 技能 / 证书

## Bullet Points 写作公式

**公式：动词 + 做了什么 + 怎么做的 + 结果是什么**

### 反面例子（差）
- 负责用户增长相关工作
- 参与了 APP 的开发
- 负责团队管理

### 正面例子（好）
- **主导**用户增长项目，通过优化邀请裂变机制，**3 个月内**新用户留存率从 20% **提升到 35%**
- **独立开发** APP 核心模块，使用 React Native 跨端方案，**节省 40%** 开发成本，覆盖 iOS + Android 双端
- **带领 5 人团队**完成产品迭代，季度需求交付率 **从 60% 提升到 95%**

### 关键原则
- **能量化就量化**：数字比形容词有说服力 100 倍
- **不要写"负责"**：负责 = 你没做什么具体的事
- **每条只讲一件事**：不要一条 bullet 里塞三个项目
- **结果导向**：HR 关心的是你做成了什么，不是你做了什么

## 动词库

### 中文
| 弱动词（别用） | 强动词（推荐） |
|----------------|----------------|
| 负责 | 主导、牵头、推动、落地 |
| 参与 | 协助、配合、支持 |
| 做了 | 搭建、设计、开发、实现、优化 |
| 管理 | 带领、统筹、协调、搭建体系 |
| 提升 | 提升、增长、翻倍、缩短、降低 |

### 英文
| 弱动词 | 强动词 |
|--------|--------|
| Responsible for | Led, Owned, Drove |
| Helped | Supported, Collaborated on |
| Made | Built, Developed, Designed, Created |
| Improved | Optimized, Streamlined, Accelerated |

## 中英文差异

### 中文简历
- 可以放照片（国内 HR 习惯）
- 教育背景可以写详细（GPA、排名、奖学金）
- 语气正式、简洁，不要太张扬
- 一页纸足够（除非 10 年以上经验）

### 英文简历
- **不要放照片**（避免歧视争议，ATS 也读不了）
- 不要写年龄、性别、婚姻状况
- 更强调 action verbs 和量化结果
- 用过去式描述过去的工作，现在式描述当前工作
- 1 page 是黄金标准（5 年以内经验）

## ATS 友好原则

ATS（Applicant Tracking System）是招聘系统，HR 筛简历第一步是机器筛。

### 必须做到：
- **用标准标题**：Experience、Education、Skills 这种通用词，不要搞成"我的旅程"、"关于我"这种花里胡哨的
- **纯文本为主**：不要用文本框、图片、表格来放关键信息
- **关键词匹配**：JD 里出现的词，你的简历里要有（比如 JD 写"用户增长"，你别只写"拉新"）
- **标准字体**：Arial、Calibri、Times New Roman、思源黑体这种常见字体
- **不要用页眉页脚**：ATS 读不到

### 不要做：
- 不要用双栏 / 侧栏布局（ATS 可能读乱顺序）
- 不要用图标代替文字（比如用个小图标表示"沟通能力"）
- 不要用颜色区分重点（没用，机器不认）

## 常见错误

1. **太长**：应届生写 3 页？HR 看一份简历平均 7 秒，你写 3 页没人看
2. **太水**：全是"具有团队合作精神"、"学习能力强"这种废话
3. **太假**：吹得太离谱，面试一问就露馅
4. **格式乱**：字体不统一、对齐乱七八糟、有错别字
5. **没重点**：所有经历都写得一样详细，HR 找不到你的亮点
6. **投所有岗位都用同一份**：至少根据 JD 调一下关键词和排序
