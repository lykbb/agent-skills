# 浏览器连接与页面入口

## 使用 Tabbit

有本环境的 `tabbit` Skill 时，先读其操作文档；下面保留基础连接方法供迁移使用。Tabbit CLI 只是浏览器控制工具，不是已卸载的得到大脑 CLI。不要为使用本 Skill 重新安装得到大脑 CLI。

使用稳定启动器，不使用应用包内的版本化路径，不读取 `endpoint.json`，不自行启动浏览器后台服务。

- macOS／Linux：`"$HOME/.local/bin/tabbit-cli"`
- Windows PowerShell：`& "$env:LOCALAPPDATA\Tabbit\LocalAgent\bin\tabbit-cli.exe"`

### 发现现有标签页

```sh
"$HOME/.local/bin/tabbit-cli" create --task "得到大脑资料"
```

读取返回的 `tabs`，匹配 `biji.com`、标题、当前标签和任务所有权。不要输出其他标签的敏感 URL。确认列表未截断；若已有目标页，用返回的实际 `tabId` 作为后续 `nodejs` 的 `--tab` 参数先取得该页。

`create` 只返回库存，不自动取得现有标签。浏览器库存 `tabId` 不等于运行时的 `p1` 等页面标签。`claimed` 是其他任务占用的页，不要强行抢占；同一任务内通过 `pages()` 和 `usePage()` 选择已拥有的页面。

只有没有可复用页面时，才按下面的方式打开知识库列表：

```sh
"$HOME/.local/bin/tabbit-cli" nodejs --task "得到大脑资料" --request-id open-getnote-library <<'JS'
await page.goto("https://www.biji.com/subject", {waitUntil: "domcontentloaded"});
return await tabbit.observe({frames: "none", maxChars: 6000});
JS
```

任务名在一次任务中保持不变；每个新程序使用新的 `--request-id`。以上请求 ID 是示例，重新开展任务时应生成本次的新 ID。页面状态改变后重新观察，再选择实际可见的按钮和输入项。

### 操作与验证

- 根据最新快照选择角色、名称和范围，例如确认页面确有“添加资料或新建文件夹”后使用 `page.getByRole("button", {name: "添加资料或新建文件夹", exact: true})`。
- 弹窗内按钮在 `page.getByRole("dialog")` 中定位，避免把别处的“确定”点错；隐藏插件也可能产生同名元素。
- 用条件等待和状态验证，不固定睡几秒就假设处理完成。打开新标签、文件选择或弹窗前，先准备相应事件等待；上传用当前工具支持的文件选择流程，不凭空构造路径。
- `nodejs` 成功结果读取 `result.value`。若返回 `resourceId`，使用 `resource` 分页读到 `eof`；快照自身被截断时重新限定区域提取，资源分页不能补回被省略的正文。
- `queued`／`running` 使用原任务名、原请求 ID 查询 `receipt`，每次等待不超过 60 秒。换 ID 重发会变成第二次操作，尤其不能用于重复导入。
- 传输失败不等于没提交。先观察页面和目标条目，再决定恢复；连接失败使用 `diagnose`，并遵守本环境 Tabbit 的恢复文档，不调用隐藏接口。
- 登录或验证码需要用户处理时，报告 `AUTHENTICATION_REQUIRED`，返回当前页链接，保留页面。

查询某个已提交程序的状态示例：

```sh
"$HOME/.local/bin/tabbit-cli" receipt --task "得到大脑资料" --request-id open-getnote-library --wait-ms 60000
```

完成读取与验证后，用户本机保留页面，不自动清理标签。明确属于云端的浏览器，可以先关闭本任务创建、下载或资料读取已完成且不再需要的临时页；保留已有页面、其他任务页面、目标笔记、草稿和等待用户处理的登录页。环境及清理范围见 [临时转写与云端资源管理](temporary-transcription.md)。然后结束任务：

```sh
"$HOME/.local/bin/tabbit-cli" finish --task "得到大脑资料"
```

普通 `finish` 释放页面所有权并保留剩余标签组；在云端也不等于已经关闭无用页面。不要用 `--discard`，除非用户明确要求关闭全部任务标签。

## 得到大脑页面入口

以下知识库菜单和链接弹窗在 2026-10-12 的浏览器页面中核对过；界面更新后以现场快照为准，不把旧名称当固定接口。此核对没有提交新笔记、上传文件或验证实际转写。

| 目的 | 页面路径／控件 |
| --- | --- |
| 找知识库 | `biji.com/subject` → 我创建的／我订阅的 → 目标库；库内可见“切换知识库” |
| 创建精选专库 | 知识库列表 → 当前创建入口 → 名称“优秀文章”；先确认同名可写库不存在，不把库内“新建文件夹”当成创建知识库 |
| 查库内内容 | “搜索”；“全部／笔记／文件／直播／博主”；左侧知识库文件列表 |
| 打开添加菜单 | 可见“添加”，按钮可访问名称“添加资料或新建文件夹” |
| 新建文字 | 添加 → 写笔记 |
| 生成链接笔记 | 添加 → 粘贴链接 → “生成一条链接笔记”弹窗 |
| 链接输入 | 输入项“粘贴或者输入链接”；补充要求输入项“整理这条链接的核心内容” |
| 提交链接 | 弹窗内“确定”；这是实际入库操作，需要用户的保存／导入授权 |
| 收入已有笔记 | 添加 → 选择已有笔记 |
| 导入本地内容 | 添加 → 添加文件／导入 Markdown／上传图片／导入音视频 |
| 长期收录 | 先查已有账号订阅；添加 → 订阅直播／博主 → 使用受支持的主页／名片或直播链接；先核对费用与范围 |
| 增加目录 | 添加 → 新建文件夹；仅按用户要求组织资料 |

原稿入口没有在此菜单核对中验证，不预设笔记详情的固定选择器。打开实际笔记后，重新观察正文、原文／转写入口、加载状态和显示范围。

## 博主一次订阅，持续复用

此流程依据 [官方博主订阅说明](https://doc.biji.com/docs/DjTGwfNFpicM7mk6IcrczAq7nve)整理，没有实际建立新订阅。该说明明确支持抖音博主，并描述按日收录前一天的新视频；其他平台、当前周期及可收录内容以现场核对为准，不用旧宣传页保证支持。

1. 在目标知识库的“博主”列表或当前订阅管理中查重，匹配平台、账号及主页链接，不只比较昵称。已有正常订阅则打开并复用；暂停、异常或等待同步先检查原因，不删除重订。
2. 取得目标账号主页／分享名片链接，而不是单条视频链接。抖音浏览器主页或分享入口能提供有效账号链接时直接使用；无法取得时可请用户提供名片链接。[官方名片说明](https://doc.biji.com/docs/N1sTwkCmFiEWoBk2ch2ckEWKnvh)给出的 App 路径是博主主页 → 更多 → 分享名片 → 复制链接；不要为取链接自动操作用户手机。
3. 在用户有写入权限的目标库打开“添加 → 订阅直播／博主”，观察当前弹窗，按它支持的账号类型和输入项填写一次。不要把主页链接放入“生成一条链接笔记”后就声称完成订阅。
4. 提交前核对解析出的账号身份、目标库、收录范围及额度／费用提示。持续收录已获准且没有新增付费或范围变化时正常提交；出现付费、开通会员或其他新权限要求时先确认。
5. 读回订阅记录、状态与显示的来源，记录目标库和账号链接；后续访问复用该记录和自动更新内容。订阅成功不等于首次同步已经完成，也不等于全部历史内容已收录。
6. 需要补录用户指定的旧作品时先检查库内是否已有，再仅补缺失条目。订阅入口不支持该平台时如实说明，与用户确认是否接受一次性逐条收集；不声称第三方视频下载器也能让得到大脑自动更新。

## “优秀文章”专库：创建、分类与单篇链接导入

创建库入口可参考 [官方创建知识库说明](https://doc.biji.com/docs/VdKMwBmEsisMzCk4NCYcIoxNnYd)。以下是操作指导，没有实际创建库、文件夹或文章笔记；现场入口、权限和额度提示优先。

1. 确认文章属于用户点名或已授权挑选入库的范围，取得单篇原始 URL，核对标题、作者、原始发布日期和实际阅读范围；仅有搜索卡片或 AI 摘要时不虚称读过原文。
2. 在知识库列表查找用户有写入权限的“优秀文章”。存在就复用；没有时从知识库列表的创建入口新增该名称的独立库，再读回确认。不是在当前订阅库中使用“新建文件夹”代替新库。保留私有访问范围，不自行公开分享、重命名或删除其他库；创建遇到费用或权限限制时停止并说明，不开通会员。
3. 在“优秀文章”内按原始链接和标题／作者查重。已存在则读取并确认归类，不重复新建。来源订阅库有同一文章但精选库尚未收录时，按用户的独立精选要求使用原始链接另建笔记，不移动、删除或改写原来源条目。
4. 依据文章主主题复用已有分类。需要新分类且确有文章要放入时，使用该库“添加 → 新建文件夹”，例如 AI，并读回确认父库和文件夹名称。不要建立同义重复分类或先造一批空目录。
5. 在正确库／分类上下文使用“添加 → 粘贴链接”，粘贴原文 URL 并按任务要求提交。不能假设在某文件夹打开弹窗就必然保存到该目录；若页面不支持直接指定文件夹，按当前可用的归类功能将本次新建笔记归入已确定分类，再读回核对。
6. 等待解析状态并打开原文，检查来源和可读范围；仍在处理中或没有原文时如实报告。主题明确的新文章直接归类；需暂放“新加文章／待分类”收件箱时注明原因，后续整理已有条目前按移动／修改规则确认。
7. 交付明确位置，例如“优秀文章 / AI / XX文章”，附实际笔记或来源链接与状态。精选库及正式笔记不随云端暂存清理删除，也不把一次文章导入当成已建立作者订阅。

产品功能不确定时查 [官方使用文档](https://doc.biji.com/)；不要用本文的核对日期或旧页面状态代替当前权限、额度和处理结果。
